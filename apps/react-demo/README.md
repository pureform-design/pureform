# react-demo

`@pureform/react` on the Panda target: a single page with the button and checkbox in their
variants and states (sizes, colors, icons, a toggle, a composed button, an indeterminate parent
checkbox, and a form that submits and resets), with a switch between left to right and right to
left. (`solid-demo` is a set of small apps instead; the shared suites in `tests/component-suites`
check the two bindings against each other.)

```sh
bun x pureform generate          # writes .pureform/ from pureform.config.ts (needs the packages built)
bun x panda codegen              # writes styled-system/, which .pureform/ imports
bun run dev                      # the bundler plugin regenerates .pureform/ on start and on config changes
```

Through omni, `build` runs `prepare` first, which runs the `generate` task and then `panda
codegen`.

## Where it sits

```
@pureform/react ──► PureformProvider registry={registry}
        ▲                                  │
        │                    .pureform/index.ts  (generated by the bundler plugin or pureform generate)
        │                                  │
   src/App.tsx               .pureform/web/*.ts ──► styled-system/recipes/* (Panda codegen)
                                                         ▲
                          panda.config.ts ── panda.pureform.ts ── pureform.config.ts
```

- `pureform.config.ts` started as a copy of `solid-demo`'s config: Material's defaults, the
  `teal`, `sharp`, and `dense` themes, and the named densities (`solid-demo`'s has since gained a
  named theme per shape and density its settings offer); `panda.pureform.ts` compiles it with
  `prefix: "pf"`.
- `.pureform/` is generated and ignored, as in the other demos: the bundler plugin
  (`@pureform/bundler/vite` in `vite.config.ts`) writes it when `vite dev` or `vite build` starts
  (builds prune it to what the page uses), and `bun x pureform generate` (`@pureform/cli`, the
  omni `generate` task, before Panda's codegen) writes it without Vite. Both take `pureform.codegen.ts`'s options: the Panda adapter's codegen for `button` and
  `checkbox` only (the allow-list: the components the React binding has). The command runs under
  Node, as Vite does (`bun x` follows the bin's shebang): the preset computes a shape morph
  differently under Bun, which changes the registry's hash. It holds `index.ts` (the registry, both
  entries static),
  `web/button.ts` and `web/checkbox.ts` (the class factories over Panda's recipes),
  `registry.d.ts` (types the components' variant props from the registry; the tsconfig includes
  `.pureform/` since TypeScript's globs skip dot folders), and `panda.ts` (`staticCss`, which
  `panda.config.ts` uses). Don't edit it.
- `panda.config.ts` uses `@pandacss/preset-base` and the pureform preset only; `styled-system/`
  is generated and ignored.

## Worth knowing

- Theme switching and runtime overrides wait for p5b; the provider's `theme` prop does nothing yet.
- Its only test is a smoke test: `test:e2e` (`vitest.config.e2e.ts`, over the demo's own Vite
  config, after `prepare`) renders the page in Chromium, its buttons styled by Panda's stylesheet,
  without an error; its global setup, `@pureform/vitest-config/browser-warmup`, compiles the page's
  modules before the test opens it. The components are tested in `@pureform/react`, and the shared
  browser suites in `tests/component-suites` cover the cross-cutting rules for React and Solid
  together (with the Panda fixture's registry, `tests/panda-fixture`, whose button and checkbox
  match this one's).
