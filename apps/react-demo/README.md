# react-demo

`@pureform/react` on the Panda target: a single page with the button and checkbox in their
variants and states (sizes, colors, icons, a toggle, a composed button, an indeterminate parent
checkbox, and a form that submits and resets), with a switch between left to right and right to
left. It's the React counterpart of `solid-demo`'s components page (`/components`).

```sh
bun scripts/generate.ts   # writes .pureform/ from pureform.config.ts (needs the packages built)
bun x panda codegen       # writes styled-system/, which .pureform/ imports
bun run dev
```

Through omni, `build` runs `prepare` first, which runs the `generate` task and then `panda
codegen`.

## Where it sits

```
@pureform/react ──► PureformProvider registry={registry}
        ▲                                  │
        │                    .pureform/index.ts  (generated by scripts/generate.ts)
        │                                  │
   src/App.tsx               .pureform/web/*.ts ──► styled-system/recipes/* (Panda codegen)
                                                         ▲
                          panda.config.ts ── panda.pureform.ts ── pureform.config.ts
```

- `pureform.config.ts` is a copy of `solid-demo`'s config (Material's defaults, the `teal`,
  `sharp`, and `dense` themes, the named densities), so both demos produce the same recipes;
  `panda.pureform.ts` compiles it with `prefix: "pf"`.
- `.pureform/` is generated and committed: `scripts/generate.ts` runs `@pureform/generate` with
  the Panda adapter's codegen for `button` and `checkbox` only (the allow-list: the components
  the React binding has). It holds `index.ts` (the registry, both entries static),
  `web/button.ts` and `web/checkbox.ts` (the class factories over Panda's recipes),
  `registry.d.ts` (types the components' variant props from the registry; the tsconfig includes
  `.pureform/` since TypeScript's globs skip dot folders), and `panda.ts` (`staticCss`, which
  `panda.config.ts` uses). Don't edit it; p4c moves the demo onto `pureform generate` and the
  bundler plugin.
- `panda.config.ts` uses `@pandacss/preset-base` and the pureform preset only; `styled-system/`
  is generated and ignored.

## Worth knowing

- Theme switching and runtime overrides wait for p5b; the provider's `theme` prop does nothing yet.
- No tests of its own: the components are tested in `@pureform/react`, and the shared browser
  suites in `tests/component-suites` cover the cross-cutting rules for React and Solid together
  (they render with `solid-demo`'s registry, whose button and checkbox match this one's).
