## Deviations from the design

- **`useStyleFactory` returns the factory in the provider's environment**, not the bare entry:
  the bare factory is the base theme's light scheme (p4b-rn), which a component under a dark or
  themed provider would never want. Recorded in §5.3.
- **Components select through `rn-adapter`'s hooks**, fed the registry's factories by
  `StylesProvider`, rather than calling `useStyles`: the animated hooks, ripples, SVG drawing, and
  token tweens need the whole `Selected` and the provider's context, and reusing them kept the
  demo's output identical. `useStyles` is the public selection hook (§5.3's table).
- **Motion engines** are a provider option (`engine`), not in the design: the demo's Animated vs
  Reanimated and SVG switches became four engine objects, so an app imports react-native-svg and
  Reanimated only through the engine it picks. Components start over (`withEngine`, keyed by the
  engine's name) when it changes, since engines' hooks differ.
- **The icon fill is a lowered value**, not evaluated in the binding (p1d's two options): the
  `FILL` axis lowers to a private key moved out of the style. Recorded in §9.6.
- **Overlays are surfaces** (menu, dialog, snackbar, tooltip): no open state, positioning, or
  timers; the select opens its menu in a `Modal`, as the demo did.
- **`motion` replaces `reducedMotion`** on the binding's provider; `rn-adapter`'s styles-based
  provider keeps `reducedMotion`.
- **The demo doesn't prune** (`prune: false`): the runtime mode draws every component by name.

## Stubs and gaps

- **No compound parts** (`Button.Root`, …), `slotProps`, `unstyled`, or slot-keyed styles on
  React Native: ready-made components only. A later phase can add them on the same anatomy.
- **Overlay behavior** (open/close, dismissal, positioning, snackbar timing, tooltip triggers),
  **keyboard navigation**, and the slider's keyboard/step accessibility actions aren't built.
- **No shared component suites for React Native**: `tests/component-suites` runs Solid and React
  only; the package's own browser tests and the demo's e2e cover React Native Web.
- **Runtime themes** stay web only (the provider throws); a native runtime theme source would
  need a generator returning theme values (p5b's note).
- **Direction on a device is global** (`I18nManager`); a nested `dir` only changes selection.
- **Native pruning still isn't run by an app** (the demo sets `prune: false`).
- The user's rn-web-demo dev server on port 4313 kept the old Vite config in memory (Vite didn't
  restart on the config change); it needs a restart to serve the new page.

## Notes for the next phases

- **New React Native components:** write them like `button/button.tsx`: `usePress` for
  interaction state, `useComponentSlots(name, <binding-core selection>(props), state)`, render
  `engine.View`/`Text`/`Pressable` with `s.<slot>`, `testIdOf(anatomy, part, props.testId)` per
  part, `IconSlot` around icons, `useInk(selected, { slot })` for ripples, and export
  `withEngine(Impl, "Name")`. Add the subpath to `package.json`, `vite.config.ts`, and, if it's
  new to every binding, `COMPONENT_USAGE`.
- **Variant groups must come from the props binding-core names** (the usage spec checks it);
  compute derived groups (a FAB's `extended`, a field's icons) in the selection call, not as JSX
  props.
- **Instance tokens** are passed by the component's token names; `useComponentSlots` maps them to
  theme keys through the entry factory's `tokens`, which tweens need. A registry built by hand
  over runtime styles must pass `instanceTokenKeys` to `nativeFactory`, or tokens are taken as
  theme keys.
- **Testing on React Native Web:** alias `react-native` to `react-native-web` and
  `@react-native/assets-registry/registry` to its `AssetRegistry`, define `global` and
  `__DEV__`, and set `process.env.NODE_ENV` to development so Animated runs (see
  `packages/react-native/vitest.config.unit.ts`). Precompute styles in a Node-side command.
- **Lockfile:** edited by hand (`--lockfile-only` re-resolved emnapi, lightningcss, commander,
  aria-query, dom-accessibility-api): the package's workspace block, catalog line, and package
  line, and the demo's new dependencies; `bun install --frozen-lockfile` reports no changes.
- `apps/solid-demo/solid-env.d.ts` changes on workspace builds; restore it before committing.
