## Built

### `@pureform/generate` (`src/usage.ts`, `src/generate.ts`, `src/adapter.ts`)

```ts
// component → group → values. A component or group left out keeps every value, and so does a
// group listed as ["*"]; a "*" group stands for every group not listed ({ "*": [] }: defaults).
type VariantUsage = Readonly<Record<string, Readonly<Record<string, readonly string[]>>>>;
interface Usage {
    readonly components: readonly string[]; // drawn; names the config lacks are ignored
    readonly variants?: VariantUsage;
}
const normalizeVariants: (variants, components, shape) => VariantUsage;
// only the given components and real groups; each narrowed group plus its default, config
// order; groups that keep every value dropped; {} when nothing narrows
const keepsValue: (variants, name, group, value) => boolean;
const narrowConfig: (config, components, variants?) => CoreConfig;
// only those components; each recipe's variants filtered, compound variants whose `match` names
// a dropped value dropped; tokens, themes, base styles shared (not copied)
const resolveRelative: (from: string, specifier: string) => string | undefined; // from imports.ts

GenerateOptions.usage?: Usage;          // components = allow-list ∩ usage; lazy names left out dropped
GenerateResult.components: readonly string[]; // what was generated
CodegenContext.variants?: VariantUsage; // normalized; always set by generate ({} unpruned)
```

The hash gains `variants` only when they narrow something, so glue made with a usage that narrows
nothing (or no usage) keeps its old hash: react-demo's committed glue didn't change.

### Adapters

- **Panda** (`codegen/static-css.ts`): `staticCssModule(components, themes, rules?)`,
  `type StaticCssRule = Readonly<Record<string, readonly string[]>>`. A narrowed component gets
  `[{ <every group>: <values> | ["*"] }]`; others keep `["*"]`. Checked with `panda cssgen` by
  hand: a rule's unlisted group generates only its default, `["*"]` all values, Panda adds the
  defaults itself and always emits every compound variant of a generated recipe.
- **CSS / Tailwind**: `subsetConfig(config, components, variants?)` is now `narrowConfig`; the
  codegens pass `context.variants`.
- **Native**: precomputes `narrowConfig(context.config, context.components, context.variants)`.
  Declared `states` come from the narrowed styles (could shrink in a pruned build; types only).
- Factory modules and `registry.d.ts` never change with variants.

New dependencies: `@pureform/anatomy`, `@pureform/binding-core`, `oxc-parser`; dev:
`@pureform/css-adapter`, `@pureform/preset` (the fixture spec). `bun.lock` edited by hand
(`bun install --frozen-lockfile`: no changes); omni dependencies too.

**When it prunes:** Vite: in the `config` hook when `command === "build"` and not
`build.watch` (the scan skips Vite's `build.outDir` too); other bundlers: in `buildStart` unless
`this.meta.watchMode`; never in dev servers. Metro (`withPureformGlue`): only with
`prune: true`, scanned once before Metro starts. The runner is created once with the usage, so
regenerations (config changes) reuse it. It prints `pureform: pruned the glue to the N components
the app uses (…), and the variant values it selects` (Vite's `info`), or warns `pureform: pruning
kept every component and variant, since <reasons>. Pass the components to keep in the plugin's
prune.keep and fix these, or set prune: false.`

**In place:** a pruned build writes pruned glue to `.pureform/`; dev and `pureform generate`
write the full glue back (hash differs). The CLI never prunes and ignores `prune` in a glue file.

## What pruning sees and misses, and the escape hatches

**Sees** (every script under the root or `include`, plus relative imports out of it; skips
`node_modules`, dot folders, `dist`, `build`, `coverage`, `styled-system`, the glue, the bundler's
outDir, `*.{spec,test,e2e,stories}.*`, `__tests__`, `__mocks__`, `.d.ts`):

- component subpath imports (side-effect, named, namespace) → the entries `COMPONENT_USAGE` lists;
  type-only imports and `internal/*` ignored;
- JSX on them (`<Button>`, `<Button.Root>`, `<ns.Button>`): string/number/boolean literals,
  `undefined`, templates without expressions, `a ? "x" : "y"`, a bare attribute (`"true"`);
  anything else → that group keeps every value; a spread → every group;
- a component referenced other than as a tag (`as={Button}`, `<Dynamic component={X}>`, passed,
  re-exported, dynamically imported) → every group of every entry it draws;
- `useClasses`/`useStyles(literal, selection)`: an object or a function returning one (one
  `return`, or an expression body; `as const`, parens unwrapped); groups not written → defaults;
  a spread or anything else → every value; `tokens` ignored;
- `useClassFactory`/`useLazyClassFactory`/`useStyleFactory(literal)` → every value;
- `useComponent(<anatomy from @pureform/anatomy>, { selection })` (named or namespace import);
- `registry.entry("x")`/`.preload("x")` on the glue's `registry` (from `virtual:pureform/registry`
  or a relative import of the folder) or a `useRegistry()` result; imports of
  `.pureform/web|native/<name>` → every value;
- `<PureformProvider defaults={{ … }}>` with written-out values → added to used components;
  any other `defaults` (or a spread on the provider) → no variant narrowing at all.

**Keeps everything and warns on:** a parse error; a registry hook, `registry.entry`, or
`.preload` with a name it can't read; `useComponent` with an anatomy it can't name; an unknown
component subpath; the root's registry hooks re-exported (`export { useClasses } from …`,
`export * from "@pureform/solid"`) or the root imported dynamically; the glue imported as a
namespace, re-exported, or dynamically.

**Misses** (documented in the bundler README): components drawn from packages in `node_modules`
(a wrapping design system); a registry reached through `usePureform().registry` or passed under
another name; a registry hook assigned to another name (`const use = useClasses`; a wrapper
that calls it with a parameter bails instead, so it stays safe); scope shadowing (over-inclusive
only). It isn't the module graph: unused files count.

**Escape hatches:** `prune.keep`, `prune.variants: false`, `prune.include`/`exclude`,
`prune: false`, and the allow-list (`components`), which pruning only narrows further.

## Deviations from the design

- **The scan runs before the build, over the app's files, not the module graph after tree
  shaking** (§7 named `moduleParsed`/`generateBundle`). Panda reads `staticCss` in
  `configResolved` and Tailwind and the CSS target's stylesheet are transformed during the build,
  so the usage has to exist before any module does. Unused files under the root count. Recorded in
  §7.
- **Pruned glue is written in place** to `.pureform/` (no separate folder): Panda's config imports
  `./.pureform/panda` directly, which no bundler hook can redirect. Apps that commit the folder,
  or whose folder other tools read during builds, opt out (react-demo, solid-demo).
- **Metro doesn't prune by default**: one config serves and bundles.
- **The bindings' internals aren't scanned**; `COMPONENT_USAGE` in binding-core says what each
  component draws and which props reach the registry, guarded by its spec.

## Stubs and gaps

- **Tokens, themes, `@property`, keyframes, and shapes aren't pruned**: the CSS and Tailwind
  stylesheets keep them whatever is used (most of the remaining CSS). A later phase could drop
  shape paths and keyframes no kept rule reads.
- **solid-demo and react-demo don't prune** (`prune: false`): the browser suites read
  solid-demo's `.pureform/` and Panda stylesheet (concurrent builds would break them), and
  react-demo commits its glue. Panda pruning is covered by the panda-adapter spec and the by-hand
  react-demo comparison above, not by a committed end-to-end test.
- **Native pruning isn't run by any app** (rn-web-demo doesn't use the bundler yet; p8 may):
  covered by the rn-adapter spec (pruned factories equal the full ones over every kept
  combination of the preset) only.
- **Rollup and esbuild** still aren't installed; their pruning path (`buildStart`, `meta.watchMode`)
  is tested through Rolldown and direct hook calls.
- **`@pureform/react-native`** (p8) isn't in the repo yet: `COMPONENT_USAGE` and the hook names
  (`useStyles`, `useStyleFactory`) already cover `@pureform/react-native/<subpath>`; if p8 names
  hooks or subpaths differently, update `usage.ts`.

## Notes for the next phases

- **New components (any phase):** add the subpath to `COMPONENT_USAGE` with the entries it draws
  and only the groups its props pass through unchanged; `usage.spec.ts` fails until the subpath,
  the anatomies, and the props agree. A new hook that reads the registry by name goes in
  `REGISTRY_HOOKS` (else the scan misses it).
- **p8 (`@pureform/react-native`):** the scan already treats `@pureform/react-native/<subpath>` as
  a binding and `useStyles(name, selection)`/`useStyleFactory(name)` as registry hooks. A Metro app
  prunes with `withPureformGlue(config, { prune: true })` for release bundles. The usage spec
  reads Solid and React sources only; extend it to the React Native binding's folders.
- **Apps that commit `.pureform/` or share it with tests** should set `prune: false`, or accept
  that builds rewrite it (`pureform generate` restores it).
- **The demo comparison script** (`/tmp/opencode/compare.mjs`, not committed) is a quick way to
  check a pruned build renders like the full one; it takes two `dist` folders and an ignore regex.
