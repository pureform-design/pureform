## User decisions, as built

- **Input and Textarea take `value`/`defaultValue`/`onValueChange`** (`PlainTextProps` in
  binding-core) alongside the native props, whose own `onChange`/`onInput`/`onChangeText` still run.
    - React's logic is in `react/src/field/plain-text.ts`, Solid's in `solid/src/field/plain-text.ts`;
      React Native uses `useControllable` in `field/text-control.tsx`.
    - A form reset reports `reason: "reset"`. React Native has no form reset.
    - The cases have a `state` (typing `{End}!`, `"Ada"` → `"Ada!"`) and `form.resets`, so the
      controllable and forms suites now run for both.
- **Only `plainTextarea` is prefixed**, as c10a named it.
- **`aria-disabled` on the label is kept.**
- **A rendered ErrorText marks the field invalid** (`fieldState`: `invalid ?? described.error`, or an
  `error`). An explicit `invalid={false}` still wins.
- **Each piece is its own module**: `src/{label,input,textarea,description,error-text}/<piece>.tsx`
  and `field/context.ts` in all three bindings.
    - In `usage.ts`, each piece's subpath lists only its own entry. `field` lists all six, since it
      re-exports Textarea.
    - The usage spec's `drawnBy` now follows a named module, not its whole folder, and follows
      re-exports.
- **The Field context is exported** (`FieldContext`, `useField` from the `field` subpath).
    - NativeSelect reads it in all three bindings. `nativeSelectProps(props, fieldsetDisabled, field)`
      merges the field's id, disabled, required, `aria-invalid` and `aria-describedby`, with the
      select's own props winning.
    - On React Native's native path the trigger is labelled by the field's label.
- **The box is shared**: `preset/src/components/plain-box.ts` (`PLAIN_BOX_TOKENS`, `plainBoxStyle`).
    - The input's and textarea's preset snapshot is unchanged.
    - nativeSelect's tokens were renamed `hoverColor` → `hoverOutlineColor` and `textColor` → `inputColor`.
    - The select's invalid border now reads `aria-invalid` only, not `:invalid`, so a required
      select with a placeholder isn't red on load.
    - The select reads its own `hover` and `disabled`, not `slot("select", …)`, because
      `:has(:disabled)` would match a disabled option.
    - The `native-selects` screenshot didn't change.
- **NativeSelect's `ripple`:** dropped from the web's needs, but **kept in `usage.ts` for React
  Native**. Its Material Menu fallback ripples, and pruning would otherwise drop that style. The
  usage spec marks it React Native-only (`NATIVE_ONLY`) and the web select as `STATE_LAYER_ONLY`.
  This departs from the decision as worded; see the open questions.
- **The React Native platform-menu path stays optional and unverified** (no device).
- **NativeSelect `multiple`** (`NativeSelectValue = string | readonly string[]`, with helpers
  `nativeSelectValues`, `nativeSelectValue` and `sameNativeSelectValue`):
    - Web and React Native Web: `<select multiple>`, read from `selectedOptions`. A form submits
      every chosen value, and a reset puts back the default array.
    - iOS and Android, with `@react-native-menu/menu` 2.0.0
      ([types](https://github.com/react-native-menu/menu/blob/master/src/types.ts)): each action has
      `state: "on" | "off"`, a press toggles it, and `attributes.keepsMenuPresented: true` keeps the
      menu open (iOS 16+ only). The package documents `state` as iOS 14+, so Android may show no
      check.
    - Material Menu fallback: checkbox items that toggle without closing.
    - The trigger shows the chosen labels joined by ", ".
    - Solid types the value props by `multiple` (`NativeSelectValueProps`, a union, so Root's props
      are type aliases there). React and React Native take the plain union.
    - Cases: `nativeSelectMultiple` (examples, state `["m"]` → `["m","l"]`, submits two entries,
      resets, required, invalid, and keyboard arrows choosing one). Binding specs cover multiple
      and the select inside a Field.

## Refactoring hints (for r9)

- **Plain box:** `plain-box.ts` is the shared home. The search bar's root is close to it. The input's
  and textarea's token blocks still repeat `placeholderColor`/`paddingBlock` (tokens are per component).
- **Plain text value:** React's and Solid's `field/plain-text.ts` repeat the native select's reset
  logic (`shown`, `resetsTo`, report on reset). One binding-core-shaped helper per binding (a
  "native control value" hook) would serve the select, the inputs and a future plain checkbox.
- **Field registration:** `useDescribes` (React, Solid) and React Native's `useFieldPiece` are alike;
  each binding's `field/context.ts` is the home.
- **Select grouping:** `nativeSelectGroups` is still `selectItemGroups` retyped (c10b's hint).
- **React Native's Material-menu fallback** repeats the select's menu wiring (c10b's hint), and now
  has checkable items for `multiple`.
- **What must not change:** the field primitives' preset snapshot, the `nativeSelect` snapshot (as
  of `8d372296`), the `plain-fields` and `native-selects` screenshots, the indication fixtures, and
  the targeted e2e above.

## Open questions

- **`ripple` in native-select's usage:** kept for React Native's Material Menu fallback, against the
  decision's wording. Dropping it would mean React Native's menu fallback loses its ripple style
  when pruned.
- **Unread `stateDraggedOpacity` on nativeSelect:** handled with a spec exception. Narrowing
  `PLAIN_BOX_TOKENS` instead would avoid declaring it.
- **Ready-made NativeSelect's own `aria-describedby`:** set on the component, it replaces the
  Field's ids instead of joining them (it goes on the Select part, after Root's merge).
- **The `@react-native-menu/menu` paths**, including multiple and `keepsMenuPresented`, need a
  device check before the peer is advertised.
- **Value typing:** the value union in React and React Native, against the discriminated type in
  Solid. r9 could align them.
- **Server rendering of Solid's controlled textarea value:** covered by the suites' SSR runs
  (passed), but Solid has no unit spec for it.

## User decisions

- NativeSelect keeps `ripple` in its usage entry (React Native's Material menu fallback draws one).
- `aria-describedby` joining and value types by `multiple`: r9.
- The iOS/Android menu path stays unverified until a device check.
