## Built

Extracted, with output unchanged:

- **Dialog-machine parts** (new `packages/solid/src/dialog-parts.tsx` and
  `packages/react/src/dialog-parts.tsx`): `dialogParts({ name, anatomy, backdropAnatomy?,
rootProps, selection, machineProps, modal?, positionerLayout, contentLayout? })` returns
  `Root`, `Trigger`, `Backdrop`, `Positioner`, `Content`, the `context`, and two part builders:
  `part(key, display, element, machine?)` and `trigger(key, display, machine?)`. Root runs Zag's
  dialog machine, the presence and `stackPositioner`, and provides `scope`, `backdrop`, `api`,
  `presence`, Root's `props`, the positioner and surface refs (Solid: `setSurface`/`surface()`;
  React: `positioner`/`surface` refs and `latestApi`). The dialog, the full-screen dialog and both
  sheets are built from it in both bindings. Their exported prop types stay; each part is typed
  through a `const X: (props: XPartProps) => …` alias. Behavior is kept: Solid hides a standard
  sheet's backdrop through the layout, React renders nothing for it (`modal` option).
- **binding-core:** `DIALOG_BEHAVIOR_PROPS` (`components/dialog.ts`) is the shared tail of
  `DIALOG_ROOT_PROPS`, `FULLSCREEN_DIALOG_ROOT_PROPS` and the sheets' root props (it replaces the
  private `SHEET_BEHAVIOR_PROPS`). The key lists are unchanged. `partAsRoot(value, part)`
  (`parts.ts`) is the four copies of `backdropTestId`/`backdropUnstyled`.
- **Plain machine buttons** (`useMachineButton(props, machine, disabled?)` in each binding's
  `interaction.ts`): it gives the part its own source, the handlers that emit to it, and
  `combinePartProps([...machine, handlers])`, and returns the `render` options. Users: the
  snackbar's action and close, the toast's action and close triggers, the split button's leading
  button, the tags input's chip remove, and the FAB menu's close trigger. The split button's
  trailing button still maps the menu trigger's props by hand. The full-screen dialog's actions
  have no own source, so they use the dialog parts' `trigger`.
- **Glyphs:** `GLYPH_PATHS` (`close`, `back`, `dropDown`) and `TOAST_GLYPH_PATHS` in the new
  `packages/binding-core/src/glyphs.ts`. Each binding's `glyphs.tsx` draws them through one
  private `Glyph`, and now exports `DropDownArrow` too. The select, autocomplete and split button
  (`ArrowIcon`) copies of the arrow, and the search view's `BackIcon`, are gone. The SVG markup is
  the same.
- **Select-like field parts** (new `packages/{solid,react}/src/select-field-parts.tsx`):
  `selectFieldParts(context, itemContext)` returns `Label`, `LeadingIcon`, `PrefixText`,
  `SuffixText`, `SupportingText`, `Positioner`, `Content`, `ItemGroup`, `ItemGroupLabel`, `Item`
  and `ItemLabel`, read through the structural `SelectFieldApi` (both Zag's select and combobox
  APIs fit). The select and the autocomplete use it. `Root`, `Container`, `Input`,
  `TrailingIcon` and the select's `HiddenSelect` stay their own.
- **Preset select field** (`select.ts`): `selectField({ name, description, editable }, groups,
densities)` builds the select and the autocomplete. `editable` is the only difference: the
  autocomplete's input keeps the text cursor. `autocomplete.ts` is now a call to it.
- **Overlay animation runs** (`overlay.ts`): `motionAnimation(name, duration, easing,
fillMode = "none")`, one `animation()` call over theme roles. `overlayMotion`'s steps, the sheets'
  `sheetMotion` and the search view's icon travel use it.
- **React Native modal chrome** (new `packages/react-native/src/modal.tsx`):
  `useModalOverlay(component, { open, defaultOpen, onOpenChange, closeOnEscape })` returns `open`,
  `setOpen`, `presence` (dialog motion), `close` and `show`, with Escape and back-button
  dismissal. `ModalWindow` is the `Modal` with its own `PortalHost`. `ModalScrimLayer` is the
  scrim, the press outside, and the positioner (at the dialog's layer) around the presence view.
  Users: the dialog, both sheets (all three parts), the full-screen dialog (window and state, no
  scrim), and the search view (window and state; its own `show` measures the anchor).
- **React Native notification pieces:** `SurfaceButton` (new `surface-button.tsx`) is the
  snackbar's and the toast's action/close button: indication from the anatomy entry for the part,
  slot styles, test id and `IconSlot`. Each component keeps its `withEngine` wrapper and display
  name. `useHeldTimeout(open, duration, onTimeout)` in `overlay.tsx` is the hover- and
  press-held timer, with `holdProps` for the `Pressable`, used by `QueuedSnackbar` and `ToastItem`.

## Not extracted, with the evidence

- **Notification colors and placement (snackbar vs toast):** they share no values. The snackbar
  is the inverse surface (`inverseSurface`, `inverseOnSurface`, `inversePrimary`); the toast is
  `surfaceContainerHigh` with type accents. Placement differs too: the snackbar is a positioned
  root with `overlayMotion`, while Zag positions the toast's `group` and each toast moves through
  its transform transition. The text action is the same apart from key order: the toast has
  `flexDirection: row` between the colors and the type, the snackbar doesn't. So one builder
  would reorder keys. The shared pieces (`pressableRoot`, `interactiveColors`, `surface`) are
  already shared.
- **Preset modal chrome:** the sheets, full-screen dialog, search view and modal rail already
  share `surface()`, `overlayMotion`/`DIALOG_MOTION`, the `scrim` component and the `dialog`
  layer. Folding `sheetMotion` into `overlayMotion` (c3b's hint) would rename the sheets' fade
  keyframes (`sheetFadeIn` → `overlayFadeIn`) and drop `SHEET_KEYFRAMES` entries, which changes
  the output (see proposed change 1). Only the animation run is shared.
- **The search view's binding Root (Solid/React) on the dialog parts:** its Root runs Zag's
  combobox as well as the dialog machine, places itself by `variant`, and has no backdrop or
  trigger part of the dialog's kind. Only its `Positioner`/`Surface` look like the dialog's.
  Fitting it into `dialogParts` would need the factory to take a second machine. Left alone. Its
  items still repeat the menu's item parts (c3c's hint): `Menu.Items`/`Menu.ItemEntry` are tied to
  the menu context, and `selectFieldParts`' items need a select-like API.
- **The modal rail:** the bindings' navigation rail has no modal of its own (a 33-line Solid
  file; the docs say to put it in a dialog over a scrim). Nothing to share.
- **`dragToDismiss` with an axis:** only the bottom sheet drags. The side sheet has no drag
  handle here, and nothing else drags yet. It waits for a second user (c4's panes).
- **Drag handle use:** the bottom sheet is still the only user of `DragHandle` and
  `sheetDragHandleLayout`. Nothing is duplicated.
- **Text input affixes, `SupportingRow` and `Counter`** (`text-input.tsx`) **and the tags input's
  field parts:** `createTextInput` already builds them for the text field and text area. Its
  supporting text sits in a supporting row with a counter. The tags input's parts render chips
  and a wrapping container. Only `Label` and `LeadingIcon` match `selectFieldParts`, which reads
  a select-like API. Sharing those two would be a two-line wrapper per part.
- **Menu `ItemGroup`/`ItemGroupLabel` vs the select field's:** the menu's run on the menu's own
  context and scope (the `menu` anatomy's root, not a select menu anatomy), and its label takes
  `htmlFor` in React where the select's takes `group`. They stay apart.
- **The `scrollContentToTop` guard** (c3c's hint, for Zag's select and menu): this is a
  behavior question, not duplication. It's left for whoever sees the bug in the select or menu.

## Deviations from the design

None. Public additions only: `partAsRoot`, `DIALOG_BEHAVIOR_PROPS`, `GLYPH_PATHS`,
`TOAST_GLYPH_PATHS` (binding-core); `selectField` and `SelectFieldOptions` (preset's `select.ts`);
`motionAnimation` (preset's `overlay.ts`). The bindings' internal modules also gained
`dialogParts` and its types (`dialog-parts.tsx`), `selectFieldParts` and its types
(`select-field-parts.tsx`), `useMachineButton`/`MachineButtonProps` (`interaction.ts`) and
`DropDownArrow` (`glyphs.tsx`). React Native gained `modal.tsx` (`useModalOverlay`,
`ModalWindow`, `ModalScrimLayer`), `surface-button.tsx` (`SurfaceButton`) and `useHeldTimeout`
(`overlay.tsx`). Nothing exported was renamed or removed. The sheets' private
`SHEET_BEHAVIOR_PROPS` became `DIALOG_BEHAVIOR_PROPS`.

## Refactoring hints

- **Helpers that look generic:** for c4 authors to reuse rather than copy:
    - Anything on Zag's dialog machine in Solid/React (c4's panes, a modal rail or toolbar sheet):
      `dialogParts`, with `part`/`trigger` for the extra parts. Pass `modal` for a backdrop that
      hides when not modal, and `contentLayout` for presses back on a surface in a pointer-events
      none positioner.
    - Any modal in React Native: `useModalOverlay`, `ModalWindow`, and `ModalScrimLayer` for a
      surface over the scrim.
    - Any plain `<button>` part that shows indication with no machine emitting for it:
      `useMachineButton` (Solid/React), and `SurfaceButton` in React Native.
    - Any timed, hover-held notification in React Native: `useHeldTimeout`.
    - A select-like field (c5's time input suggestions, a combobox variant): `selectField`
      (preset) and `selectFieldParts` (bindings).
    - Glyphs: add a path to `GLYPH_PATHS` and a one-line export to each `glyphs.tsx`.
    - Keyframe runs: `motionAnimation`.
    - A Root that also renders another component's root (a backdrop, a scrim): `partAsRoot` for
      its `testId`/`unstyled`.
- **Code that looks like a sibling's:** still open: the search view's items against the menu's
  (an items renderer that takes a scope and the item props), the React Native autocomplete's
  anchored list against the select's and the menu overlay's placement, and the progress/slider
  tracks (r4).
- **Suggested home:** as above.
- **What must not change:** `JSON.stringify(pureform())` (dump it with a script that imports
  `packages/preset/src/index.ts`), the `.pureform/` dirs from a fresh `omni run generate -f all`,
  the preset snapshots, indication fixtures and screenshots.
