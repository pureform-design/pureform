## The merge's changes

1. **Instance springs (f2e's answer).**
    - `@pureform/generate`: `componentShape(spec, config?)` adds `springs`, the tokens whose value
      is a spring (literal, a `springs` role alias, a `dynamic` default, every platform choice, or
      with the config an alias to another component's spring token). The declarations write
      `springs: "indicatorSpring";` beside `tokens`, and a `SpringRoleRegistry` with the config's
      role names.
    - `@pureform/styling`: `InstanceTokens<C>` gives a spring token `InstanceSpringValue`
      (`SpringNode | SpringRole`) and every other token a `TokenValue`; a spring on another
      token, a plain value on a spring token, or an unknown role is a type error. A component the
      types don't know still takes either anywhere. `tokenStyle(tokens, vars, springs?)` /
      `withTokenStyle(..., slot, springs?)` write a role's name as
      `<var>-duration: var(--springs-<role>-duration)` (and `-easing`).
    - Web adapters (css, panda; tailwind through css): factories emit
      `const springs = { indicatorSpring: "--springs" }` (`instanceSpringVars`, css-lowering,
      under `tokenPrefix`) and pass it.
    - React Native's factory: a string naming one of the theme's roles sets the token's five keys
      to that role's values in the environment's theme.
    - Tests: shape, declarations, types, `tokenStyle`, the css codegen's every-token check and the
      browser suite's panda-factories check (spring tokens take a role), and the RN factory.
2. **`onClose` on every close (f2c's answer).**
    - binding-core `closeAsker()` (`components/sheet.ts`, root entry): asks an `onClose`, acts on a
      boolean at once or a promise when it settles (rejection = no), and ignores an answer after
      a later question or `cancel()`. It replaces both copies (`sheet-drag.ts`'s `asking` and
      React Native's `latestDismiss`).
    - `askingDismissProps(onClose, props, asker, close)`: Zag dialog props that stop Escape and a
      press outside (only where Zag would close) and ask first.
    - Web: `dialogParts` (React, Solid) takes an `onClose` option, adds those props, and gives
      parts `asker` and `requestClose`; the drag handle's press asks instead of closing through
      Zag. `dragToDismiss(handle, sheet, dismiss, onClose?, asker?)`: `dismiss(kept)` closes and,
      once the binding has rendered that (React: a post-commit effect; Solid: after its update),
      calls `kept` if the sheet is still open. The `requestAnimationFrame` check is gone.
    - React Native: `useModalOverlay` takes `onClose`, so Escape, the back button and the scrim
      ask; it returns `closeNow` and the shared `asker`, which the sheet's handle press and drag
      use.
    - Tests: `closeAsker`, `askingDismissProps`, the drag's shared asker and post-render refusal
      (binding-core); Escape, the scrim, the handle's press and a drag in React and Solid; Escape,
      the scrim and the handle in React Native.
3. **Composed grouped menus.** `markMenuGroupEdges(content)` (binding-core `/dom`) marks the
   content's own groups (not a submenu's) `data-first`/`data-last` in DOM order and follows
   changes (a `MutationObserver`). React's and Solid's `Content` run it; `ItemGroup` no longer
   takes `first`/`last`, and the machine's `first`/`last` option (f2c) is removed again, so there
   is one mechanism. React and Solid specs compose a menu with a loose item and three groups.
4. **Popup `scale` and the visual suite.** `visual.e2e.test.tsx` passed unchanged (55/55):
   screenshots show popups at rest, where `scale` and `transform: scale()` draw alike. **No
   screenshot was re-recorded.** The component suites' "animates in as it opens" check, which
   expected the popup's movement on `transform`, now takes `transform` or `scale` (f2c only ran
   `-t "Toast|submenu whole"`, so it hadn't seen this).
5. next.md §2's "slider inset icon cutoff following the theme" entry and its line in §1 are
   dropped (f2b's answer: the clipped ring follows `outlineWidth`, and f2b made the clearance a
   token).

## Open questions

- **Role vars on Panda:** web factories name a role's vars `--springs-<role>-…` under the
  registry's `tokenPrefix`, as the css and tailwind stylesheets and the panda fixture write them.
  A Panda app with its own Panda `prefix` would need that prefix passed as `tokenPrefix`.
- **React Native role detection:** the factory takes a string as a role when the theme has
  `springs.<name>.stiffness`; it doesn't check that the token is a spring (the types do).
- **Composed menu SSR:** `data-first`/`data-last` come from the DOM after mount, so a server
  render of a grouped menu draws its outer groups' corners square until hydration (menus render
  closed, so this is rarely visible).
- **`onClose` and controlled `open`:** closing through `open` (or the app's own controls calling
  `setOpen`) doesn't ask; only the sheet's own ways of closing do.
- The machine's `first`/`last` option from f2c is removed; say if the machine should keep it.

## Answers to the open questions

- **Role vars on Panda:** the Panda adapter defaults `tokenPrefix` to Panda's own prefix when the
  app sets none, so a role's var names always match (r8).
- **React Native role detection:** the factory also checks at runtime that the token is a spring
  token, from the registry's spring-token list; any other string stays a string (r8).
- **Composed menu SSR:** known and accepted; the outer corners are square until hydration.
- **`onClose` and controlled `open`:** by design, closing through `open` doesn't ask `onClose`
  (as in Radix and MUI); document it in the sheets' docs (r8).
- **Machine `first`/`last`:** restore the option as an override: the bindings mark the groups
  themselves by default, and a group's explicit `first`/`last` wins. Document it so (r8).
