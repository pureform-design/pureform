## Built

Extracted, with output unchanged:

- **Corner morph** (`packages/preset/src/components/shared.ts`): `cornerMorphTokens(rest,
squareRadius, pressedRadius)` gives the five tokens `cornerRadius` reads (`radius` full,
  `squareRadius`, `pressedRadius`, the `square` flag set by `rest`, `toggles`), and
  `cornerMorphVariants(rest)` gives the `corner` and `toggle` variant groups (the resting
  corner's entry stays empty). `RestingCorner = "round" | "square"`. Used by `button.ts`,
  `icon-button.ts` (rest `round`) and `chip.ts` (rest `square`). The FAB has no morph and
  is unchanged.
- **Tiles** (new `packages/preset/src/components/tiles.ts`, exported from the package root):
  `POSITIONS`, `Position`, `positionCorners(outer, inner)` and `TILE_RADII` moved from
  `list.ts`. `list-item.ts`, `menu.ts` and the spec import them from there. Binding-core
  gets `tilePosition(index, count)` and `TilePosition` (`components/list.ts`, exported);
  `listItemPosition` now wraps it.
- **Affix field** (`packages/preset/src/components/field.ts`): `affixField(ref)` runs
  `fieldParts` (centered label, icons' room on the input, density) and `affixParts`, and
  its `parts(groups, densities)` returns the merged `base`, the `variants` and
  `defaultVariants` up to the affixes, `compoundVariants`, and `density`. `text-field.ts`
  and `select.ts` add only their own parts (counter and `secure`; the arrow and `cursor`).
  `COUNTER_STRUCTURE` (root → container and supportingRow → supportingText and counter) is
  shared by `text-field.ts` and `text-area.ts`.
- **Solid icon parts** (`packages/solid/src/parts.tsx`): `iconParts(use, name, part,
{ mirror })` returns `{ Part, Optional }`, a `<span>` icon part and the version
  `optionalPart` needs to build its icon once. Used by `Button.Icon`/`SecondaryIcon`,
  `Chip.Icon`/`TrailingIcon` and `ListItem.Leading`/`Trailing`. `IconPartProps` is exported
  from `parts.tsx`.
- Tests: `rows.spec.ts` covers `tilePosition`.

Output check: `JSON.stringify(pureform())` (every recipe resolved) is byte-identical before
and after. Every app's and the Panda fixture's `.pureform/` codegen (CSS, Tailwind, Panda,
React Native) is identical to a fresh generate at 4234434. Preset snapshots, indication
fixtures and screenshots pass unchanged. The whole gate passes
(`omni run build test -f all -o continue`: 102 succeeded, 0 failed), and tsc is clean in
preset, binding-core and solid.

## Not extracted, with the evidence

- **Progress vs slider track and stop geometry (c1b, c1g):** the idea is the same, but the
  expressions aren't. The progress track is `value% + gap` against `0` with `radius("full")`
  ends. Its stop is `circle`, placed by `top: (height - stopSize) / 2`. The slider's pieces
  are flag-driven (`startGap`, `endGap`, `bar`, clearance), have per-end corners and two
  orientations, and its marker uses `radius("full")`. Sharing a builder would change the
  resolved values, so this is left for c4a (wavy progress, vertical progress), when a
  second user of the slider's `Segment` builders exists.
- **React optional icon parts:** each is a ten-line destructuring function with nothing
  repeated beyond the `scope.render` call. A helper saves nothing. React Native is the same.
- **Field affixes and counter in the bindings** (`text-input.tsx` vs `select/select.tsx`):
  the affixes differ (the text input passes machine props, the select doesn't), and r3's
  "combobox and select" item covers them along with c3c's autocomplete.
- **Menu and select group rendering, modal rail wiring:** these are ten-line part functions
  on different contexts (the menu's `scope`, the select's `menu`), and the modal chrome is r3's
  item with sheets and the full-screen dialog (c2b changes the dialog first). Both are left to
  r2 and r3.
- **Snackbar row/column actions (c1f):** there is one user so far; the card and dialog
  actions don't change layout. Wait for c2b's dialog.

## Deviations from the design

None. Public additions: `cornerMorphTokens`, `cornerMorphVariants`, `RestingCorner`,
`affixField`, `COUNTER_STRUCTURE` (preset), `tilePosition`, `TilePosition` (binding-core),
`iconParts`, `IconPartProps` (solid's internal `parts`). Nothing was renamed or removed.
`positionCorners`, `POSITIONS`, `Position` and `TILE_RADII` are still exported from the
preset's root. Only the module they live in changed.

## Refactoring hints

- **Helpers that look generic:** for c2 authors to reuse rather than copy:
    - c2e's connected button group: `positionCorners`/`TILE_RADII` from `tiles.ts`, and
      `tilePosition` in binding-core, for each item's `position` variant.
    - c2c's input chip and c2e's button group items: `cornerMorphTokens` and
      `cornerMorphVariants` with `cornerRadius` and `cornerTransition` (`shared.ts`), for any
      round/square/pressed/toggle morph. Give `rest` the resting corner.
    - c2f's split button: `cornerMorphTokens` for its halves. Its inner corners are better
      driven by `positionCorners` with the morph radii.
    - Any new Solid part with an optional icon: `iconParts` (`solid/src/parts.tsx`).
    - c3c and c5 inputs with a prefix, suffix or counter: `affixField` and `COUNTER_STRUCTURE`
      (`field.ts`).
- **Code that looks like a sibling's:** still open: the Solid/React affix, `SupportingRow`
  and `Counter` parts (`text-input.tsx`, `select/select.tsx`), the menu/select `ItemGroup`
  and `ItemGroupLabel` parts, the modal rail against the dialog binding (all for r3), and
  the progress/slider tracks (r4, after c4a).
- **Suggested home:** as above. Leave `tiles.ts` for tile geometry and `shared.ts` for the
  morph.
- **What must not change:** `JSON.stringify(pureform())`. Dump it before and after with a
  script that imports `packages/preset/src/index.ts`. Also every `.pureform/` codegen
  directory, the preset snapshots, the indication fixtures and the screenshots.
