# m1: Springs foundation (output context)

Branch `m1-springs-foundation`, from main `d849f3e2`. Commits are listed by
`git log d849f3e2..m1-springs-foundation`; this file and the README tick are in the last one.

## What was built

- **Core** (`@pureform/core`): `LinearEasingNode` (`kind: "linear"`, `points: [output,
inputPercent?][]`, `linearEasing(...)`); `SpringNode` (`stiffness`, `damping` ratio, `mass`,
  `spring({ stiffness, damping, mass? })` or `spring({ duration, bounce })`); `Timing` (`TweenTiming
| SpringTiming`), which `TransitionPart` and `AnimationNode` now are (`AnimationRun & Timing`);
  `tween(property, timing)` overload; `CoreConfig.springs` and `ThemeOverride.springs`;
  `AliasPath` takes `springs`. `spring.ts`: `springAt`, `settleTime`, `dampingCoefficient`,
  `springProblem`, `sampleSpring`, `sampleCubicPath`, `linearPointsProblem`, `linearStops`,
  `linearEasingAt`, `formatLinearEasing`, `parseLinearEasing`. `validateConfig` throws
  `MotionConfigError` for bad springs, bad `linear()` points, and a spring timing with a duration
  or easing (or a tween with no duration).
- **css-lowering**: `linear` easings print as `linear(...)`; `spring.ts` (`springVars`,
  `springTokenEntries`, `springTokenGroups`, `compileSpring`); `aliasTarget` maps `springs`;
  `themeVars` writes spring vars. The CSS adapter's token vars (base and themes), Panda's tokens
  (nested `springs.<name>.{duration,easing}`, base and themes) and so Tailwind's stylesheet carry
  them. Checked that Panda 2.2 accepts the `springs` category (the fixture's `tokens/index.js`
  holds `springs.spatialFast.duration`).
- **rn-adapter**: `Spring` and `spring?` on `Transition`, `Animation`, `PresenceStep`;
  `springTokenValues` (five theme values per spring: duration, easing, stiffness, damping
  coefficient, mass); the theme resolves them as `springs.<name>.<field>`; `animate()` in
  `animate/curve.ts` runs `Animated.spring` or `Animated.timing` and is used by transitions,
  token tweens, SVG shape morphs and Animated presence; `curve()` and Reanimated's `cssEasing`
  read `linear(...)`; `timeScale` scales a spring's stiffness by 1/s² and damping by 1/s (drops
  it at 0).
- **react-native**: `OverlayMotionStep` takes `spring` in place of `duration`/`easing`, read from
  the theme's spring values and slowed by `timeScale`.
- **theme**: `SPRING_ROLES`, `SpringRole`, `MotionContract.springs`, `spring(role)` ref,
  `PATHS.spring`, resolver checks (`requireNames`/`requireKind` with a `spring` kind), lowered to
  `config.springs`, `ThemeVocabulary.springs`.
- **material**: `MATERIAL_SPRINGS` (standard and expressive), `materialMotion({ scheme, springs,
durations, easings })`, `emphasized` as the sampled path.
- **preset**: `pureform()` themes carry changed springs (base already via `theme.config`);
  `tweens(timing, ...properties)` overload; `MotionTiming`, `OverlayMotionStep` as `{ keyframes,
rtl? } & MotionTiming`, `timedAnimation(name, timing, fill)` (`motionAnimation` delegates to it).

## Decisions

- **Spring values and source.** Compose's generated token objects (v0_14_0), which give stiffness
  and damping ratio; material-components-android's `m3_sys_motion_*_spring_*` agree.
    - https://github.com/androidx/androidx/blob/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/StandardMotionTokens.kt
    - https://github.com/androidx/androidx/blob/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens/ExpressiveMotionTokens.kt

    | Role           | Standard (k, ζ) | Expressive (k, ζ) | Sampled ms (std / expr) |
    | -------------- | --------------- | ----------------- | ----------------------- |
    | spatialFast    | 1400, 0.9       | 800, 0.6          | 224 / 360               |
    | spatialDefault | 700, 0.9        | 380, 0.8          | 317 / 435               |
    | spatialSlow    | 300, 0.9        | 200, 0.8          | 484 / 600               |
    | effectsFast    | 3800, 1         | 3800, 1           | 150                     |
    | effectsDefault | 1600, 1         | 1600, 1           | 231                     |
    | effectsSlow    | 800, 1          | 800, 1            | 327                     |

    Mass is 1 throughout (Compose's springs have none).

- **Sampling.** Settle when the spring stays within 0.001 of the distance; 1000 uniform samples
  over the settle time, simplified with Ramer–Douglas–Peucker on vertical error within 0.002 (the
  tolerance loosens by 25% steps if more than 48 points remain); outputs rounded to 4 places,
  inputs to 0.01%; the last point is exactly 1. An undamped spring is capped at 10s.
- **Emphasized path method.** M3's path from material-components-android
  (`m3_sys_motion_easing_emphasized_path_data`, `M 0,0 C 0.05, 0, 0.133333, 0.06, 0.166666, 0.4 C
0.208333, 0.82, 0.25, 1, 1, 1`):
  https://github.com/material-components/material-components-android/blob/master/lib/java/com/google/android/material/motion/res/values/tokens.xml.
  `sampleCubicPath` evaluates each cubic at 400 parameter steps (x and y, since x isn't linear in
  t), then simplifies the (x, y) points to within 0.001 vertically: 44 stops. A spec checks the
  curve against points on both segments.
- **Emphasized accelerate/decelerate** stay Compose's and m3.material.io's `(0.3, 0, 0.8, 0.15)`
  and `(0.05, 0.7, 0.1, 1)`; material-components-android rounds them to `(0.3, 0, 0.8, 0.2)` and
  `(0.1, 0.7, 0.1, 1)` (noted in the code comment).
- **Reanimated** runs a spring as its sampled duration and `linear()` curve (Reanimated's
  `linear(...)`), since its CSS animations and transitions have no spring; `withSpring` would mean
  leaving the CSS model. Animated runs `Animated.spring` for transitions, token tweens, shape
  morphs and overlay steps; keyframe animations (several frames, iterations) and the tabs' slide
  keep the sampled curve.
- **Reduced motion**: no new mechanism. The part-level rule (`transitionMoves`) drops a spring on
  a moving property like any other; springs on fades keep running; an overlay's moving keyframes
  give way to a fade on the same timing. Documented in `motion.ts` and §5.8.1.
- **Perceptual springs** convert as SwiftUI and Motion do: `k = (2π / duration)²`, `ζ = 1 −
bounce` (or `1 / (1 + bounce)` below 0), mass 1, duration in ms.
- **Web var names**: `--springs-<name>-duration` and `--springs-<name>-easing`, the token ref
  `springs.<name>.duration`/`.easing`, so Panda (nested category) and the CSS adapter agree.

## Output changes

- Every web stylesheet from `pureform()` gains the twelve `--springs-*` vars (six roles × two),
  and React Native themes the thirty `springs.*` values. Nothing reads them yet.
- `--easings-emphasized` (and React Native's `easings.emphasized`) is now the `linear()` path
  instead of `cubic-bezier(0.2, 0, 0, 1)`. Components whose motion uses it: the corner morphs of
  button, icon button, chip, FAB menu and split button (`cornerTransition`), the button group's
  width, padding and corners, the navigation indicator, shaped clip-path morphs, the tabs'
  indicator slide (`indicatorEasing`), and the time picker's hand (`handEasing`). Their CSS text is
  unchanged (it reads the var); their timing curve changes.
- Snapshots: none of the existing snapshots held the emphasized value. New snapshots:
  css-lowering `spring.spec.ts`, css-adapter `stylesheet.spec.ts` (springs), panda-adapter
  `preset.spec.ts` (springs), tailwind-adapter `tailwind.spec.ts` (spring vars).
- `tests/component-suites/src/tabs-motion.e2e.test.ts` expected the standard curve on the tabs'
  slide; it now expects the emphasized `linear()` as the browser serializes it, and samples
  "partway" at a sixth of the duration (the emphasized curve is ~95% done at half).

## Refactoring hints

- **Helpers that look generic:** `sampleCubicPath` (core) for any future path easing;
  `animate()` (rn-adapter `animate/curve.ts`) for any new Animated driver; `timedAnimation`
  (preset `overlay.ts`) for keyframes on a spring or duration+easing role.
- **Code that looks like a sibling's:** the spring scaling by `timeScale` is in both
  `rn-adapter/src/react.ts` (`slowed`) and `react-native/src/presence.ts` (`overlayMotion`); a
  shared `slowSpring(spring, by)` would serve both.
- **Suggested home:** `slowSpring` in rn-adapter `motion.ts`, exported for react-native.
- **What must not change:** the sampled values (snapshots above), the spring tokens' var names.

## Open questions

- `SlideMotion` (tabs' indicator) and keyframe animations take no `Animated.spring` yet; they run
  the sampled curve. m2 can add it if the tabs move to a spring.
- An overlay step that scales on a spatial spring and fades on an effects spring needs two
  animations per step; the type allows a spring per step, but a step is still one animation.
- The settle tolerance (0.001), curve precision (0.002) and point cap (48) are this phase's
  choices; Compose's default visibility threshold is 0.01, which would give shorter durations.
- Whether to expose springs to Tailwind as a theme namespace (`--ease-*` of the curve alone
  loses the duration); left out.
