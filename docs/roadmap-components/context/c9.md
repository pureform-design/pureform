## Decisions implemented

**Popover (c9c):** opens at `bottom-start` by default (binding-core `popoverMachineProps`, React
Native's `Anchored`), as the menu. No scrim, even `modal`. The ready-made prop stays `heading`;
no `onClose`.

**FileUpload (c9b):** the drop zone stays non-clickable. `acceptedFiles`, `defaultAcceptedFiles`,
`onFileChange` are gone; the files are `value`, `defaultValue`, `onValueChange({ value,
rejectedFiles })`, through `useControllable` in both bindings (so the switch warning and
`reason: "reset"` work) and binding-core's `fileUploadValueProps`, which maps them onto Zag's names.
The case gained a `state` (a file chosen through the hidden input). A `File` can't be sent to the
server, so `StateCase.serverRendered: false` keeps it out of the server-rendering suite's "renders
the value on the server" (it still hydrates and responds). No form case: a file input submits a
`File`, which the forms suite's text entries can't express. `maxFiles` stays 1. Visual section
`file-uploads` (idle, dragged, invalid, an uploading and a rejected file) and `fileUpload` in
`RN_COMPONENTS`.

- Gate fix: the preset's `invalid` variant group is now **`error`** (`fileUploadSelection` sets it
  from `invalid` or an `error` message). React Native's adapter reads a state named like a group
  as the group, so `rn-parity`'s `aria-invalid` sample drew the error color on React Native and not
  on the web. The unread `iconColor` token was removed (the icon follows the zone's content color,
  which tints while dragged).

**Solid bindable `ownedWrite: true` (c9b, `packages/solid/src/internal/zag/bindable.ts`): kept.**
Every Zag machine's context and its state are bindables, and Zag writes them from event handlers,
effects, watches and cleanups (a hovered button unmounting ends its hover from a cleanup). Solid 2
throws `REACTIVE_WRITE_IN_OWNED_SCOPE` for a write inside an owned scope unless the signal allows
it, so any machine could hit it. Allowing it is right for all of them: the bindable is the
machine's own state, not derived data, its `latest` value already gives reads the last write
(`readingLatest`), and the hidden-input signals in the bindings already use `ownedWrite` for the
same reason. The whole gate passed with it.

**CopyButton (c9e):** reuses the `iconButton` recipe (no `copyButton` entry). The machine
(`@pureform/machines/clipboard`) now goes to `copied` only once the write succeeded:
`COPY` writes, `COPY.WRITTEN` moves it; a write that fails both ways (async API, then
`execCommand`) calls `onCopyError({ value, error })` and stays idle. `copyText` resolves `true` or
the error. React and Solid render a visually hidden `role="status"` span after the button that
reads `copiedLabel` while copied (`copyAnnouncement`, `COPY_ANNOUNCEMENT_STYLE` in binding-core).
React Native shows copied once `copy` returns (or its promise resolves), announces with
`AccessibilityInfo.announceForAccessibility`, and calls `onCopyError` when `copy` throws or rejects;
the text glyphs stay. Visual section `ratings-and-copy-buttons`.

**Rating (c9e):** visual section (sizes, a half star, a disabled read). It found a bug: the half
star was 50% of the **item** (icon plus padding), so it showed two-thirds of a star. It's now half
the icon (`calc(iconSize * 0.5)`). Gate fix: only the tokens it reads (`accent`, and the focus
ring's three; no state opacities, no container roles), so no instance token is unread.

**ColorPicker (c9d):** HSB kept, inline only (the READMEs and the gap analysis say to wrap it in a
`Popover` for a trigger). The machine now has the browser's fieldset rule
(`withFieldsetRule(…, "trackFormControl")`: Zag's effect has another name here, so
`withFieldsetRule` takes the effect's name) and no reset of its own; `form` reaches the hidden
input; both bindings own the reset (`useFormReset`, `reason: "reset"`), and the hex field ignores
its own reset so it follows the picker. The forms case (submits `#006a6a` under `name`, resets) is
in. The machines root export stays out (see r9).

**NumberField (c9a):** steppers stay side by side. The default locale is the environment's:
`numberFieldLocale(props)` is `locale`, else `navigator.language`, else the platform's `Intl`
locale, else `NUMBER_FIELD_LOCALE` (`en-US`); React Native's arithmetic defaults to it too. The
indication suite now passes the checked entry's trigger to `IndicationCase.focus(host, trigger)`,
and `focusMoves: true` says the focus is real (so the focus indicator and the source's focus are
checked as after Tab). The number field's case focuses the button it's given (a key first, then
`focus({ focusVisible: true })`), so both buttons are cased.

**Refactor rule** (guidelines §4 checks: logical, obvious, flexible):

- Done: `roundIconButton(token, size, { fill, content })` in `packages/preset/src/components/shared.ts`
  (icon box, focus ring, no border or padding, full radius, state layer). The number field's
  steppers and the input chip's remove button use it; each adds its own color, margin and
  disabled rule. Output is the same: the preset snapshots are key-sorted and unchanged, all
  longhands, so the computed styles can't differ; the indication fixtures didn't change for either.
- Not done, for r9: the secure field's visibility toggle (no icon box or state layer, so it
  shares only half). Hold-to-repeat: one user (React Native's number field); the rating doesn't
  repeat, so a `holdRepeat` helper has nothing to share yet. The code field's per-cell field
  styles: a `fieldParts` option for a self-contained slot would change `field.ts` for every field;
  not obviously safe without r9's computed-style equivalence run.

## Hints for c10 and r9

- **Reuse:** `roundIconButton` for any round icon-sized button inside a component (a clear
  button, a stepper). `numberFieldLocale` for any locale default. `StateCase.serverRendered:
false` for a value the server can't take. `IndicationCase.focus(host, trigger)` with
  `focusMoves` for buttons out of the tab order. `withFieldsetRule(machine, element, effect)`
  for a Zag machine whose form effect isn't `trackFormControlState`.
- **Don't name a variant group like a state** (`invalid`, `disabled`, `selected`…): React Native
  reads the state as the group.
- **For r9:**
    - A popover inside a dialog layers beneath it: the bindings render overlays in place (no
      portals), and the dialog's layer is above the menu's. Portalling (or a layer for nested
      overlays) is r9's.
    - The list item's `trailing` part is `aria-hidden`; the file upload overrides it
      (`slotProps.trailing["aria-hidden"] = false`) for its remove buttons. Fix it in the list item
      (drop `aria-hidden` when the trailing part holds a control, or a `trailingControl` part).
    - The machines root export of the color picker made React Native's splitter drag spec fail
      (c9d): it's still exported from its subpath only. Find the interaction (Vite's dependency
      discovery reloading mid-run is the guess).
    - The refactors declined above (visibility toggle, `holdRepeat`, the code field's cell styles),
      plus the subphases' own hints: the field part builders in each binding, the overlay root
      props (`ids`, `positioning`) shared by the tooltip, rich tooltip, menu and popover, the color
      picker's `hexOf`/draft in binding-core, React Native's `useBoxDrag`, the removable list row,
      `colorTokenVariants`' `{}` vs `{ root: {} }` for the default group (the file upload and
      rating write their own).
- **What must not change:** the preset snapshots, the new screenshots, the indication fixtures,
  the component suites for the seven components.

## Open questions

- The file upload has no form case: a file input submits `File`s. Say if the forms suite should
  learn file entries.
- The number field formats in the browser's language, so a server whose `navigator.language` (or
  `Intl` locale) differs from the browser's renders text the client re-formats on hydration.
  Apps that server-render should pass `locale`.
- The copy button's live region is a sibling after the button: an app laying out by
  `:last-child` may notice it. React Native announces through `AccessibilityInfo` instead.
- The rating's half star: the visual fixture showed it at two-thirds before the fix; the bindings'
  specs didn't measure it. Say if a geometry spec is wanted.
- Known flake seen twice this gate: Solid fade-through "drops the old page at once" (unstyled).
