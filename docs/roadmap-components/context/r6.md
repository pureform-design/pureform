## Declined, with the failing check

- **Table `RowContext`, React Native `CellContent`** (c6d): one user each; the tree's node context
  carries a node, not a cell's place (check 1).
- **Avatar machine in Solid's `Image` vs React's Root** (c7c): not duplication but a choice. Solid
  keeps the row-cost budget (an avatar of initials sets up no machine); moving React would drop
  Zag's root attributes and change its DOM. Recorded, no change (check 1: not one concept to
  share; it's a per-binding cost trade-off).
- **Slider inset icon cutoff following the theme** (c7c): needs a runtime reader of the resolved
  component tokens on every target, which doesn't exist; recorded in [next.md](../next.md) §2.
- **Expandable + swipeable list item** (c7 merge): needs the action outside the header button, a
  DOM change for every expandable item on three bindings; recorded in next.md §2.
- **`iconTrigger` for paginator and calendar steps** (c6c): machine props, default glyph and
  `mirror` default differ per caller (check 2).
- **`highlightableConnect`** for select/menu/selection list (c7a): they already share
  `itemPressProps`/`highlightedPressProps`; what's left differs per machine (check 2).
- **Menu `useMenu` vs `fab-menu`** (c7b): the common part is every Zag component's setup; the
  menu's inheritance is its own (check 2). `submenuSelection` waits for a second cascading menu.
- **Swipe drag helper** (c7c), **`caption`** (c6e), **`sortRows`** (c6d), React `iconPart` (c6a): no
  second user (check 3 can't be judged; check 2 has nothing to compare).
- **`paginatorPageAfterSize`** in machines and binding-core (c6c): one line, and neither package
  may depend on the other (check 3).
- **Stepper glyphs via `ToastIcon`** (c6b): naming coupling, not duplication; next.md §2.

  Native `iconParts` for row icons; `slowSpring` for any new spring driver (m2).
