## Refactors (leftover duplication review)

Done:

- **Web splitter release** (`binding-core/src/splitter-release.ts`, `splitterRelease` and
  `splitterRoom` from `@pureform/binding-core/dom`): React and Solid each had the same `roomOf` and
  the same ~30-line `onResizeEnd` body (find the pane, `splitterSnap`, settle the two panes with
  `settleOnSpring`, `SIZE.SET`). Output unchanged: direction suite's splitter cases and the gate.

Declined, with the check that failed:

- **Transitions:** keyed content is already `binding-core`'s page model (`startPages`,
  `changePages`, `settlePage`, `keepContents`). React's and React Native's `useTransitionPages` are
  identical bodies, but the packages share no React module (binding-core has no React dependency):
  no suitable home. The fade-through `change` line is one expression. React Native's FAB menu
  `STAGGERED`/`STAGGER` mirror the preset's `FAB_MENU_STAGGERED`/`FAB_MENU_STAGGER`, but React
  Native's runtime doesn't import the preset (only its tests do): not worth a runtime dependency.
- **Closing:** `sheet-drag.ts` and `side-sheet-drag.ts` share their pieces already
  (`createDragVelocity`, `swallowNextClick`, `settleTransition`, `closeAsker`, the release rules);
  the pointer skeleton left differs in slop (4 vs 8), when it captures the pointer, and what each
  adds (partial rests and resize vs the coplanar holder). A shared skeleton would need hooks for
  each: flexibility check fails. Dialogs' `onClose` is one `closeAsker` per binding already
  (`dialog-parts`). React Native's bottom and side sheet `left`/`latestSettle`/`latestDismiss` are
  close, but each settles to a different rest and owns its gesture: not obviously one thing.
- **Triggers and popups:** the web's Positioner/Content parts are ~12 lines of boilerplate over
  shared helpers (`overlayPositionerProps`, `presentProps`). React Native's popover, menu, FAB menu
  and tooltip repeat the `Portal` + `Anchored` + presence `View` block, but each varies in layer,
  placement, role and style; a component taking all of them as props fails the flexibility check.
  Candidate for the next wave if a fifth anchored popup appears.
- **Pointer drags:** web color picker and slider drag through Zag; React Native's three drags
  (splitter `PanResponder` with `dx`, color picker `useDrag` with `measure`, slider responder with a
  rect fallback) are the same idea, not the same code (r9d declined `useBoxDrag` too: one user).

## Fixes from the gate

- **Adapter specs (r9b):** the CSS adapter's codegen spec, the Tailwind spec and the Panda
  factories e2e expected a spring token's two vars; they now expect the exact spring's
  `-stiffness`, `-damping`, `-mass` too (snapshots updated). Intended output from r9b.
- **Solid sheets read the spring var untracked (r9b):** reading `state().registry` in the drag
  handle's ref / `onSettled` warned `STRICT_READ_UNTRACKED` on hydration (server-rendering suite,
  every Solid target). Wrapped in `untrack`; the drag reads it once at setup, as before.
- **Indeterminate wavy linear progress (r9b), a real bug:** the root clipped to the wave band plus
  the flat track's band, so the full-height bar showed through the flat band and drew as a thick
  flat bar (visual suite, `loading-and-wavy`). Now the slide keyframes also set a `slide` token
  (the indicator's own widths, registered as a number), and the indicator clips itself to the
  travelling wave shifted back by `slide × 100%`; the root only animates `waveDrift` and the track
  isn't clipped. `progress-motion.e2e.test.ts` follows; screenshot updated (the new row from r9b's
  fixture is now a wave over a flat track).
- **rn-parity "every variant value at rest":** r9b's indeterminate circular arc animates `value`
  through keyframes, so the web side read the arc mid-animation (`trackStartArc` opacity 1 vs 0).
  The iframe's animations are cancelled before reading, as the scenario's name says.
- **Timing-only flakes (r9d's list), limits raised instead of waits added:** preset
  `carousel.spec.ts` theme case 30 s; machines `presence.spec.ts` "stays until the last of an
  exit's animations ends" 20 s test / 10 s poll; React Native `presence.spec.tsx` FAB menu stagger
  60 s; rn-adapter `codegen.spec.ts` native sampling 240 s (was 120 s, seen at 124 s). None of
  them failed an assertion on rerun.

## Open questions

- **r9b's device paths are untested:** the native-driver SVG ripple and the `setNativeProps`
  shape morph ran only on React Native Web. On devices SVG ripples clip to the surface's corners,
  not an arbitrary drawn shape; the fill cross-fade matches the old blend only over an opaque
  colour.
- **r9a changed `withSetTokens`'s API** (select-then-evaluate; `evaluate` reads through a
  `read(key)` lookup). It is exported from `@pureform/rn-adapter`; anyone calling it directly
  needs the new signature. Worth a changelog line.
- **r9a:** `alignSelf: "stretch"` alone doesn't stretch an own-size root (documented, not mapped
  to `width: "100%"`); `getSizeWithHeaders` isn't on React Native Web.
- **React Native ButtonGroup:** its items say `aria-checked` on `role="button"`, which fails
  the accessibility check. Left for the renderer-neutral readers phase.
- **Indeterminate wavy track:** the track runs flat under the whole bar (as before); Compose
  leaves a gap either side of the indicator. Not changed here.
