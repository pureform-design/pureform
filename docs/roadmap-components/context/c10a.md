## Done

- **Preset** (`packages/preset/src/components/field-primitives.ts`, spec and snapshot next to it):
  six slot recipes, one look each, no variants, 0 compounds. Registered in `index.ts` and
  `pureform.ts` (79 components; gap analysis §1.8, `pureform.spec.ts`).
    - `field`: `root` only, a flex column with a `gap` token. Spacing only.
    - `label`: `root` (labelLarge, `color`; dimmed by `aria-disabled`), `requiredIndicator`
      (`requiredColor`, the error role). The root is an `inlineFlex` row so the mark follows the
      text in either direction (the direction suite caught bidi placing it wrong in an inline
      label).
    - `input` and **`plainTextarea`**: the same box (`boxStyle` in the file): border in
      `outlineColor`, `hoverOutlineColor` on hover, `errorColor` on `[aria-invalid=true]`
      (`slot("root", "invalid")`, so a `required` empty input isn't red on load, as the portable
      `invalid` state, `:invalid`, would make it), disabled colours; `radius("extraSmall")`; the
      state layer of the text colour (`stateLayer`); the focus ring (`focusVisible`); bodyLarge.
      Block padding is `paddingBlock - outlineWidth + densityOffset / 2`, so the box is 40px at
      the default density and follows the theme's. No `boxSizing` in core: the field's column
      stretches the box instead of `width: 100%`.
    - The input's date and time pickers: `::-webkit-calendar-picker-indicator` (rawRules) is
      redrawn as Material's calendar icon (a clock for `[type=time]`) with `clipPath:
path(evenodd, …)` filled with `indicatorColor` (core has no `mask`). Chromium and Safari;
      Firefox draws its own icon.
    - `description` and `errorText`: bodySmall, `onSurfaceVariant` and `error`.
    - `indication.spec.ts`: `input` and `plainTextarea` join the search bar in
      `WITHOUT_INDICATION` (they draw a state layer, but they're native inputs hovered through
      CSS, with no ripple or interaction source).

## Design that's pureform's own

Everything here: Material has no plain field. Choices: the `extraSmall` corner, a 1px outline
(not Material's outlined field's notch), 40px tall at the default density, labelLarge for the
label over bodyLarge text, bodySmall supporting lines, the error role for the required mark,
the focus ring outside the box (the theme's indication) rather than a thicker outline.

## Refactoring hints

- **Helpers that look generic:** `boxStyle` and `BoxToken` in `field-primitives.ts` (a bordered
  box with hover, invalid and disabled colours and a state layer): c10b's NativeSelect needs the
  same box, and the search bar's root is close. The input's tokens and the plain textarea's are
  declared twice (one `componentTokens` each, since tokens are per component). `supporting(color)`
  is `supportingTextStyle` without its top padding.
- **Code that looks like a sibling's:** c10b (NativeSelect) will want `boxStyle`, the chevron
  colour token (as `indicatorColor` here) and `fieldControlProps` to work inside `Field`
  (`FieldContext` isn't exported from the bindings; c10b needs it exported, or the context moved
  to its own module, e.g. `src/field/context.ts`, to read the field's state).
- **Suggested home:** `boxStyle` in `packages/preset/src/components/shared.ts` (or a `plain.ts`
  for the plain primitives); the Field context in each binding's `src/field/context.ts`,
  exported for other controls (NativeSelect, a future plain checkbox).
- **Duplicated across bindings:** the Field registration (`describe`) logic in React and Solid;
  React Native's `useControl` is like its `text-input.tsx` field's focus tracking.
- **What must not change:** the preset snapshot `field-primitives.spec.ts.snap`, the
  `plain-fields` screenshot, the indication fixtures' `input.root` and `plainTextarea.root`, the
  component suites for the six.

## Open questions

- **Input and Textarea have no controllable state** (`value`/`defaultValue`/`onValueChange` with
  `ChangeDetails`): they're the native elements with native props (`onChange` in React, `onInput`
  in Solid, `onChangeText` on React Native). So the controllable-rules suite and the forms
  suite's reset don't run for them. Say if they should take pureform's controllable contract.
- **`plainTextarea`** as the registry name (the export stays `Textarea`). Alternatives: rename
  all six with a prefix (`plainInput`, …) for symmetry.
- **The label dims through `aria-disabled` on a `<label>`** (the only portable hook for a
  non-control). Axe passed; a `data-disabled` condition would be cleaner if core had one.
- **The date and time indicator** is a clip-path path, Chromium and Safari only; Firefox keeps its
  own icon, in its own colour. React Native has no date input (Material's pickers).
- **Field's `invalid` comes from `invalid` or the ready-made `error`;** a composed `ErrorText`
  doesn't make the field invalid by itself (the app sets `invalid`). Say if mounting an ErrorText
  should.
- **The six subpaths each list all six registry entries** in usage (pruning keeps them together).
  Moving each piece to its own module would let `input` draw only `input`.
- The storybook `title` override is new shared infrastructure (generator and config type).
