## Extracted

Each passed the three checks (same concept, obvious duplication, shared code takes future
changes). Output is unchanged: no snapshot, fixture or screenshot was re-recorded.

- **`springState(spring, velocity, t)`** (core `spring.ts`): a spring's closed-form position and
  speed from 0 with a starting velocity. `springAt` is now `springState(spring, 0, t).progress`
  (the preset's sampled `linear()` snapshots are byte-identical), and rn-adapter's
  `springProgress` (f1e) converts the damping coefficient to the ratio and calls it. Before, the
  same three-case solution was written twice.
- **`springTo(value, spring, { toValue, velocity, rest, delay?, useNativeDriver })`** (rn-adapter
  `animate/curve.ts`): the one `Animated.spring` start with rest thresholds, for `animate()`
  (progress, rest 0.001) and `settle()` (pixels, rest 0.5). Units stay with the callers, which is
  why m2 declined merging `settle()` itself.
- **`springFieldNodes(value)`** (rn-adapter `lower.ts`): a literal spring's or a `springs` alias's
  five per-field nodes. The theme's component-token loop (`theme.ts`) and `springNodes`' first
  two cases (f1f's hint).
- **`springTokenEntries` from `springTokenGroups`** (css-lowering `spring.ts`): one sampling pass
  and shape, two views (Panda nests, the CSS adapter and runtime themes list by path).
- **`turnedOver(condition)`** (preset `components/shared.ts`): the 180° turn of `expandIndicator`,
  the split button's chevron and the table's sort arrow (f1d's `turnOver` hint, without folding
  in the transition: each caller keeps its own, so nothing changes).
- **`shapeTransition(role, property = "borderRadius")`** (preset `shared.ts`): the corner morphs
  (`cornerTransition`, `spatialCornerTransition`) and `shaped.ts`' clip-path `morphTransition`
  (m2's `cornersOn(role, property)` hint).
- **`swallowNextClick(element)`** (binding-core `drag-click.ts`, from `/dom`): drops the click a
  drag ends with. The sheet handle's flag-and-listener (`sheet-drag.ts`), Solid's swipe listener
  and React's `onClickCapture` (f1a's hint: the native listener works in both) now share it.

## Refactoring hints (for m3's authors)

- **Reuse:** `springState` for any spring position or speed at a time (interrupts, velocity
  hand-off); `springTo` for any new `Animated.spring` (pass the rest in the value's units);
  `springFieldNodes` for a spring-valued token on React Native; `springTweens`,
  `chevronTransition`, `turnedOver`, `shapeTransition` before writing a transition by hand;
  `swallowNextClick` after any web drag on a pressable element.
- **What must not change:** the preset snapshots, `motion.spec.ts`, `tab-indicator.spec.tsx`,
  `sheet-drag.spec.ts`, the list item swipe specs, the indication fixtures and screenshots as at
  `a342461c`.

## Open questions

  0.5 (the pixel threshold), not 0.001 like `animate()`. Animated stops only when both distance
  and speed are under it, so it looks fine, but `animate(progress, { spring, delay }, …, velocity)`
  (or `springTo` with rest 0.001) would be the matching call. Left alone: it would change output.
