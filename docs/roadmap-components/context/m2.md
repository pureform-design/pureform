## Decisions applied

Decided at the merge ([phase](../phases/m2-spring-components.md#decided-at-the-merge-2026-10-22)):

1. **Fades on effects springs.** Every overlay fade is now `effectsFast` (menu, select list,
   tooltip, snackbar, dialog, sheets, toast's opacity) and the scrim's `effectsDefault`, in the
   preset (`overlay.ts` `POPUP_MOTION`/`DIALOG_MOTION`/`SCRIM_MOTION`, `sheet.ts`
   `BOTTOM_SHEET_MOTION`/`SIDE_SHEET_MOTION`, `toast.ts`) and React Native (`presence.ts`
   `OVERLAY_MOTIONS`). Reduced motion: each moving step still gives way to its fade alone, which
   now runs on its effects spring (critically damped; m1's rule keeps springs on fades).
2. **Shrink on exit.** The popup exit is `overlayShrinkOut` (scale 1 → 0.8) on `spatialFast` with
   the fade alongside, in both the preset and React Native's keyframes. It reaches every
   `POPUP_MOTION` user: menu, select list, tooltip, rich tooltip, snackbar, docked date picker,
   FAB menu list. Compose (androidx-main, read 2026-10-22):
    - `Menu.kt` `DropdownMenuContent`: scale `FastSpatial`, alpha `FastEffects`, target
      `if (expanded) ExpandedScaleTarget else ClosedScaleTarget` with `ClosedScaleTarget = 0.8f`.
    - `Tooltip.kt`: scale `FastSpatial` to `if (it) 1f else 0.8f`, alpha `FastEffects`.
    - `SnackbarHost.kt` `FadeInFadeOutWithScale`: `animatedScale` to `if (visible) 1f else 0.8f`
      on `FastSpatial`, opacity on `FastEffects`.
    - `ModalBottomSheet.kt`: scrim alpha on `DefaultEffects`.

    https://github.com/androidx/androidx/tree/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3

3. **Dialog:** keeps the sheets' springs (`spatialDefault` in, `effectsFast` out); only its fades
   changed, by decision 1.

## Refactors

Rule: extract only if it's the same concept, the duplication is obvious, and the shared code
can take future changes.

- **Done: `springTweens`** (m2a's `spatialTweens` in `shaped.ts`, m2c's `springTweens` in
  `spring-motion.ts`). Same concept (movement on a spring role, the rest on the `short3`
  standard tween, through `motionTransition`), obvious duplicate. Kept m2c's form
  (`springTweens(role, moving, fades)`), now in `components/shared.ts` beside `tweens`: the
  explicit lists take the field label's font size and letter spacing, which `transitionMoves`
  wouldn't put on the spring. m2a's call sites (switch, slider, split button) already listed the
  moving properties first, so the CSS is identical. `spatialTweens` is gone.
- **Done: corner springs.** `spatialCornerTransition` (m2a, `shaped.ts`) and `cornerTransition`
  (`shared.ts`) differed only by role; both are now `cornersOn(role)` in `shared.ts`.
- **Done: `chevronTransition`** moved to `shared.ts`; `spring-motion.ts` removed (its spec
  stays, as `spring-motion.spec.ts`).
- **Declined: split button chevron on `chevronTransition`.** Same concept, but its transition
  has no `color` part; using `chevronTransition` adds a colour tween, an output change, not a
  refactor. It already turns on the same spring. Left for the small fix phase.
- **Declined: m2b's `settle()` vs m2c's release velocity.** Not the same mechanism: `settle`
  springs a sheet's own `Animated.Value` in pixels (the drag offset isn't a token), m2c's goes
  through the component's token transitions in progress units (`startVelocity` divides by the
  distance) so every engine runs it. Shared code would be only the ×1000 px/ms → per-second
  conversion and the `Animated.spring` physics fields, with different rest thresholds (0.5px vs
  0.001 of the distance); not worth a helper.
- **Declined: `themeSpring` vs m2c.** m2c never reads a spring role itself (the theme's
  transitions carry it), so there's no second reader. Moving `themeSpring` to rn-adapter beside
  `slowSpring` (m2b's own hint) is left for the refactor phase.
- Output check: preset specs all pass with no snapshot change after the refactor.

## Refactoring hints

- **Helpers that look generic:** `springTweens`, `chevronTransition`, `cornerTransition`,
  `spatialCornerTransition` (`preset/src/components/shared.ts`); `animations(...)` (core);
  `settle` and `animate(..., velocity)` (rn-adapter); `themeSpring` (react-native `presence.ts`).
- **Code that looks like a sibling's:** `morphTransition` in `shaped.ts` is the corner builder on
  `clipPath`; a `cornersOn(role, property)` could take it if a third clip-path morph appears.
  `timingOf` in react-native `presence.ts` reads `springs.<role>.*` beside `themeSpring`.
- **Suggested home:** `themeSpring` beside `slowSpring` in rn-adapter `motion.ts`, exported from
  `/animated` (m2b's hint).
- **What must not change:** the preset snapshots above, `spatial-springs.spec.ts`,
  `spring-motion.spec.ts`, `overlay.spec.ts`, react-native `presence.spec.tsx`, and the
  browser suite's `reduced-motion.e2e.test.ts` expectations.

## Open questions

Collected from [m2a](m2a.md), [m2b](m2b.md), [m2c](m2c.md); the ones the merge answered are
left out (fades on springs, popup exit).

- **Shape roles (m2a):** Compose uses `DefaultEffects` for button, icon button and split button
  morphs (no bounce) and `FastSpatial` for chips (marked TODO in `Chip.kt`).
- **Slider (m2a):** Compose doesn't animate the thumb; keyboard steps and the pressed size here
  spring on `spatialFast` (a little bounce under expressive).
- **Split button chevron (m2a):** no Compose token; `spatialFast`. See the declined refactor.
- **Tabs on React Native (m2a, m1):** the slide runs the sampled curve, not `Animated.spring`.
- **Removed tokens (m2a):** `indicatorDuration`/`indicatorEasing`/`handDuration`/`handEasing`
  removed outright; a component token can't hold a spring ref without core support.
- **Dialog roles (m2b):** borrowed from the sheets; confirmed at the merge.
- **React Native sheets (m2b):** run the dialog's motion, not a slide from their edge; a refused
  close after a drag stays where the drag left it; the drag wrapper `Animated.View` may change a
  standalone sheet's layout. All three are in the small fix phase ([next.md §0](../next.md)).
- **Web drag dismiss (m2b):** the drag's `translate` settles back while the exit slides out;
  Compose animates the offset itself to hidden.
- **Web velocity (m2b, m2c):** CSS transitions can't start at a velocity, so the web settles a
  sheet and a swipe from rest.
- **Table sort arrow (m2c):** doesn't turn; needs a sort-direction state in core.
- **Chevron and label overshoot (m2c):** under expressive, `spatialFast` (ζ 0.6) overshoots the
  chevron's 180° turn and the label's font size.
- **New at the merge:** the shrink on exit reaches the docked date picker and the FAB menu's list
  too (they share `POPUP_MOTION`); Compose's FAB menu animates its items differently. The toast
  (not Material) fades on `effectsFast` but doesn't shrink.
