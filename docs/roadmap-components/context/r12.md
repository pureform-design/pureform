# r12: Multi-target codegen (output context)

Commits: see `git log main..r12` (merged with main at ts71, fix-storybook-8 and the
`@typescript/typescript6` restore).

## Built

- **generate** (`packages/generate/src/targets.ts`): `generateTargets` takes
  `targets: { <name>: { target, options, components? } }` (a single `target` stays a shorthand
  for one target; both at once, or a name clashing with an entry, is rejected). Each target
  writes `.pureform/<name>/full/` and `.pureform/<name>/pruned/`, so a build and a dev server
  never overwrite each other. Top-level entries (`index.ts`, `panda.ts`, `styles.css`, ...)
  re-export `full/` of the first web target; several targets also get per-target entries
  (`.pureform/web.ts`, `.pureform/native.ts`). One usage scan serves every target. Files of
  the older flat layout are removed. `targetsOf`, `entryFile` and `OUTPUT_ENV`
  (`PUREFORM_OUTPUT`, lets scripts loaded outside the bundler pick `pruned/`) are exported.
- **Types:** only `.pureform/registry.d.ts` declares `@pureform/styling`, generated from the full
  output, so `tsc` and the editor don't depend on dev vs build. `full/` and `pruned/` hold no
  module declarations; an app's `.pureform/**/*.*` include keeps working. No tsconfig `paths`.
- **bundler** (`plugin.ts`, `metro.ts`, `options.ts`): generation stays in Vite's `config` hook
  (other bundlers: `buildStart`); serve/watch writes `full/`, build writes `pruned/`.
  `resolveId` redirects each `.pureform/` import to the target (Metro and Vite environments
  aliasing `react-native` to `react-native-web` get the native one; a per-file pattern
  override for mixed setups) and the output folder.
- **cli:** `pureform generate` writes every target's `full/`; `--prune` writes `pruned/` too.
- **storybook-web:** web and native targets in `pureform.codegen.ts`; the run-time
  `pureformRn()` plugin is gone, React Native stories use generated styles.
- READMEs of generate, bundler, cli and storybook-web describe targets and the layout.

## Refactoring hints

None: the work is one feature across generate, bundler and cli, without copies between them.
`entryFile`/`targetsOf` in `packages/generate/src/targets.ts` are the shared pieces the bundler
and cli already use.

## Open questions

- The plain `.pureform/` entry is typed from the default (first web) target; multi-target code
  that wants native factory types must import `.pureform/native`. Revisit if that confuses users.
- The type test runs on a temporary fixture app rather than a real demo directory, to stay
  fast and hermetic; the demos were checked by hand (tsc after build and after dev).
- Storybook story tests filtered by `-t "Button|Menu|Progress"` matched only 6 tests over three
  projects; a wider narrow run may be worth it if story names don't contain the component.
- Under load, react-native unit specs (render counts, spring timing) and component-suites
  overlay animations fail now and then; they predate r12 and may need longer waits.
- `cog install-hook` fails in a worktree (`.git` is a file); commits were checked with
  `cog verify`. r12 commits before the main merge keep their non-conventional messages for the
  commit-msgs cleanup.
