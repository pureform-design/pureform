## Not extracted, with the evidence

- **The split button's trailing corners:** `runCorners` would reorder its four corner keys
  (end corners first today), which changes the resolved recipe's key order and the CSS order.
  They stay inline. The "pressed-or-rest corner" helper c2f suggested has only that one user.
- **Popup chrome (tooltip, rich tooltip, menu, dialog, full-screen dialog):** they already share
  `overlayMotion`/`POPUP_MOTION`/`DIALOG_MOTION` (`overlay.ts`) and `surface()` (`shared.ts`).
  What remains differs in values (level, layer, padding, radius) and in key order (the menu
  spreads `surface` before `overlayMotion`, the tooltips after it), so one builder would change
  the output. The `Caret` part has one family of users (both tooltips).
- **Group layouts (button group vs tags input):** the button group is a flex row with a
  blended gap. The tags input is a wrapping field built on `fieldParts`. They share no style.
  The "items to parts by index" loops in the bindings are each a `map` and a `tilePosition`.
- **Input chip vs filter chip colors:** both are a state-layer background and selected/disabled
  states, but the input chip puts its border before `states` and the chip's outlined fill after
  it. Only the shape (`chipShape`) is shared.
- **Solid/React FAB menu Root/List/Item vs Menu:** the FAB menu runs its own item list (pills,
  its own close trigger) on the same machine. A `useMenuRoot` would cover about fifteen lines
  per binding and would have to move the menu's context. Left for c4c (toolbar overflow),
  which would be a third user.
- **Dialog vs full-screen dialog binding parts, RN modal chrome:** r1 and c2b assign them to r3
  with c3b's sheets, which are the third user.
- **`labelledOrHidden` (badge vs avatar root props):** the rules differ (the avatar's `img`
  element takes `alt`, the badge hides only its small size). Two five-line ternaries.
- **The plain-button pattern** (own source + `useInteractionHandlers` on a `<button>`: snackbar,
  split button, input chip remove, full-screen dialog actions): each call site passes a
  different machine prop set. A helper would only wrap two hook calls, so it was left for r3,
  where c3a's toasts add more.
- **The `flexWrap` workarounds:** see the proposed changes below.

## Proposed intended changes (not done)

Core now has `flexWrap` (c2c), but each replacement changes output, so neither was made:

1. **Text field `supportingRow`** (c1a): the counter could sit in a wrapping root row without
   the wrapper. That removes a part from `textField`/`textArea`'s anatomy, the bindings'
   `SupportingRow` parts and the generated anatomy, and it changes the CSS and snapshots.
2. **Snackbar `longAction` layout** (c1f, the comment in `snackbar.ts`): `flexWrap: wrap` on
   the root would let the actions wrap instead of the layout switching the `actions` wrapper to
   a column. Its computed styles and the `new-components` snapshot change, and the RN rendering
   of wrap needs checking.

## Deviations from the design

None. Public additions only: `RunAxis`, `runCorners`, `positionCorners`' optional `axis`,
`GROUPED_TOKENS`, `groupPositionVariant`, `chipShape`, `ChipShapeToken` (preset), `Menu.Items`
and `MenuItemsProps` (Solid), `Menu.ItemEntry` and `MenuItemEntryProps` (React),
`useAnchoredOverlay` and `AnchoredOverlayProps` (react-native's internal `overlay.tsx`),
`followHighlight` (machines' internal `interaction/highlight.ts`), and `CloseIcon` (the
bindings' internal `glyphs.tsx`). Nothing was renamed or removed. `groupCorners` and
`GroupCornerToken` are still exported.

## Refactoring hints

- **Helpers that look generic:** for c3 authors to reuse rather than copy:
    - Any run of tiles or connected buttons: `positionCorners(outer, inner, axis)` and
      `runCorners` (`tiles.ts`), with `tilePosition` (binding-core) for the index.
    - A button that sits in a button group: `GROUPED_TOKENS`, `GROUP_INNER_RADII` and
      `groupPositionVariant`.
    - A chip-like pill: `chipShape`.
    - c3c's search view or autocomplete suggestions as menu rows: `Menu.Items` (Solid) and
      `Menu.ItemEntry` (React).
    - Anything React Native opens from a trigger (c3b's sheets if anchored, c4c's toolbar
      overflow): `useAnchoredOverlay`, then `Portal` and `Anchored`.
    - A close, dismiss or remove cross (c3a's snackbar and toast, c3b's sheets, c3c's search
      view's clear button): `CloseIcon` from `glyphs.tsx`. Add other shared glyphs there, such
      as the split button's and select's drop-down arrow.
    - A list whose highlight is keyed by another context field: `followHighlight`.
- **Code that looks like a sibling's:** still open, mostly for r3: the dialog/full-screen
  dialog part factories and RN modal chrome (with c3b's sheets), the plain-button pattern (with
  c3a's toasts), the field parts (text input, select, tags input, c3c's autocomplete), and the
  drop-down arrow SVG (split button, select).
- **Suggested home:** as above. Shared glyphs go in each binding's `glyphs.tsx`, and overlay
  state in react-native's `overlay.tsx`.
- **What must not change:** `JSON.stringify(pureform())`, which you can dump with a script that
  imports `packages/preset/src/index.ts`. Also the `.pureform/` dirs from a fresh
  `omni run generate -f all`, not from `build`, which writes only the used components. Plus the
  preset snapshots, indication fixtures and screenshots.
