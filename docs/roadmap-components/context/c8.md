## Decisions implemented

**Shared (binding-core `drag.ts`, refactor rule):** `createDragVelocity` (moved from
`components/splitter.ts`) and `chooseAnchor({ anchors, at, velocity, velocityThreshold,
positionalThreshold? })`, which is Compose's anchor rule. A fling goes to the nearest anchor in its
direction, or the nearest overall if there isn't one. A slower drag without a positional threshold
goes to the nearest anchor (`PaneExpansionState`). With one, it follows `AnchoredDraggable`'s
`computeTarget`: still, the nearest anchor; moving, the next anchor once the drag is
`positionalThreshold(distance)` past the one behind, else back. `splitterSnap` and `sheetRelease`
both use it, and the sheet's drag measures its speed with `createDragVelocity`. Declined: moving
`splitterMoveBy`/limits or the sheet's rest bookkeeping (component-specific).

**Bottom sheet (c8a):**

- `partiallyExpandable` defaults to `true` (Compose's `skipPartiallyExpanded = false`).
  `partiallyExpandable={false}` turns it off (`sheetPartiallyExpandable`). The prop stays as the
  off switch, so there's no deprecated alias.
- `expanded` (controlled) and `defaultExpanded` (default `false`, so it opens partly) sit beside
  `onExpandedChange`. `sheetOpeningRest` gives the rest at each open. `dragToDismiss` now returns
  `SheetDrag`, which is the stop function plus `.rest(rest)`. React and Solid call it after each
  render or change, so a change the app didn't take settles back. React Native does the same.
- Thresholds are Compose's, read 2026-10-23 on androidx-main:
  `material3/SheetDefaults.kt` `BottomSheetDefaults.PositionalThreshold = 56.dp` and
  `VelocityThreshold = 125.dp`; `BottomSheet.kt` (`AnchoredDraggableDefaults.flingBehavior` with
  `state.positionalThreshold`); `foundation/gestures/AnchoredDraggable.kt` `computeTarget` and
  `AnchoredDraggableMinFlingVelocity = 125.dp`. The anchors are fully open, partly open (top at
  half, only when the sheet is taller than half: `isPartiallyExpandedAnchorAvailable`) and hidden.
  `SHEET_POSITIONAL_THRESHOLD = 56` (px) and `SHEET_VELOCITY_THRESHOLD = 0.125` (px/ms) replace
  `SHEET_DISMISS_SHARE` and `SHEET_FLICK_SPEED`, which were removed (named in the binding-core
  README). Closing is now just the hidden anchor under the same rule: 56px down from the lowest
  rest at a slow speed, or let go still nearer hidden than open.
- Re-placing: on the web, a `ResizeObserver` on the surface plus the window's `resize`. React
  Native uses the sheet's layout and `useWindowDimensions`. While open and not dragged, the sheet
  jumps to the new partial offset, or to fully open if it's now too short (`onRest` reports
  `movable: false`).
- Body focus: `focusableWhileOverflowing` (binding-core `/dom`) gives the body `tabindex="0"` only
  while its content overflows, and leaves a tabindex the app set alone. The case's
  `slotProps.body.tabIndex` workaround is gone. React Native has no equivalent (axe is web-only).

**Splitter (c8c):** a snap settles on `SPLITTER_SETTLE` (`spring(0.8, 380)`, Compose's
`PaneExpansionState`) from the release velocity. On the web, `settleOnSpring` (beside
`settleTransition` in `settle.ts`, sharing its inline-transition code) sets a sampled `linear()`
`flex-grow` transition on the two panes beside the divider. On React Native, `settle()` drives an
`Animated.Value`, with the panes wrapped in an `Animated.View`. Reduced motion jumps. Unchanged:
the default anchors (`SPLITTER_ANCHORS`), `minSize` 0 (the app's choice), `DragHandle` stays
separate, and React Native is ready-made only.

**Context trigger (c8b):** stays a part (`Menu.ContextTrigger`) plus the ready-made `contextTrigger`
prop. Zag 1.46's menu hard-codes its long press (`waitForLongPress`, 700ms, in
`menu.machine.mjs`), so the delays can't be unified. The READMEs document 700ms on the web and
`Pressable`'s 500ms on React Native, and that a pressable nested in the area keeps its own touches.

**Gate fixes** (one fixing agent): Zag's splitter re-applied `defaultSize` on a late
`ResizeObserver` report and threw before its first measure. `@pureform/machines/splitter` now wraps
the machine and skips a re-measure when nothing changed, and the React and Solid dividers measure
first if needed. The React Native spring spec waits for layout.

## Refactoring hints (for c9 / r9)

- **Reuse, don't copy:** `chooseAnchor` and `createDragVelocity` (`binding-core/src/drag.ts`) for any
  anchored drag (list item swipe, carousel-free snaps); `settleOnSpring` / `settleTransition`
  (`settle.ts`) for any settle from a release speed. The list item swipe still has its own speed
  and threshold code (m2/c8a hint, r9's).
- **Still duplicated:** React's and Solid's sheet `DragHandle` rest bookkeeping (`lastRest`,
  `onExpandedChange` only on change, the controlled sync), which a `sheetRestTracker` could hold.
  React Native restates `dragToDismiss`'s rest logic. The React and Solid splitters share
  `roomOf`, the trigger's pointer bookkeeping and now the panel lookup for the settle.
- **What must not change:** `drag.spec.ts`, `sheet-drag.spec.ts`, `splitter.spec.ts`, the bindings'
  sheet and splitter specs, `bottom-sheet.e2e.test.ts`, the Splitter component suites.

## Open questions

- `onExpandedChange` also fires when an uncontrolled sheet reopens at a different rest than it
  closed at (c8a's behaviour, kept). Say if it should fire only for drags and presses.
- With Compose's 56px rule, a slow short drag down closes a sheet much sooner than the old
  quarter-of-height rule did. That's intended (Compose), but it's a visible change.
- The web settles to `flex-grow` on the panes; the app's own inline `transition` on a panel would
  be overwritten for that settle.
- Zag's 700ms long press: if Zag ever exposes it, set 500ms on both.
- The machines splitter wrapper patches Zag's internals (`resizeObserver` measure). Recheck on
  Zag upgrades.
