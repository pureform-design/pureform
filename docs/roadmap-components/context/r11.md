## Done

- **New package `@pureform/binding-dom`** (`packages/binding-dom`): `package.json` with `.` and
  `./indication` exports (`development`/`default` conditions), `project.omni.yaml`, tsconfigs,
  `vite.config.ts`, `vitest.config.unit.ts` (browser mode, with `emulateReducedMotion`), README and
  CHANGELOG. In the core train (`cog.toml`, `CORE_TRAIN_PACKAGES`). React and Solid depend on it;
  React Native doesn't.
- **Moved to binding-dom** (with their specs, by `git mv`): all of the old `/dom` entry (`dom.ts`
  is now binding-dom's `index.ts`): carousel-row, collapse, drag-click, sheet-drag, side-sheet-drag,
  sideways-drag, splitter-release, list-item-swipe-settle, scroll-focus, settle, menu-drill-motion,
  menu-groups, menu-submenu-room, reveal, slide, toolbar-dom, tooltip-long-press, toast-swipe,
  web-theme; and `indication-host.ts`.
- **Indication:** binding-core's `IndicationTarget` fields are `IndicationElement`, which is
  `unknown` unless a platform augments `IndicationPlatform`; binding-dom's `/indication` declares
  `element: HTMLElement`, so web code sees `HTMLElement` as before. binding-core's
  `materialIndication`/`DEFAULT_INDICATION` no longer carry a `web` half (they're name, layer,
  tokens); binding-dom's `materialIndication`, `DEFAULT_INDICATION` and `webIndication` add
  Material's ripple, the same way React Native adds its native half. `IndicationHost` applies
  `webIndication`, so binding-core's built-ins passed straight to a web provider still ripple.
  binding-core no longer depends on `@pureform/js-effects`.
- **Mixed component files:** FabMenu's `fabMenuListProps` (the key handling) moved to binding-dom;
  Dialog's and Popover's `initialFocusEl`/`finalFocusEl` left the core contracts
  (`DialogFocusProps`, `DIALOG_FOCUS_PROPS`, `dialogFocusMachineProps` added in both bindings'
  `dialogParts`, so the dialog, full-screen dialog and both sheets keep them; `PopoverDomRootOwnProps`,
  `POPOVER_DOM_ROOT_PROPS`, `popoverDomMachineProps`); SearchView's input getter
  (`searchViewDomDialogProps(props, input)`; core's `searchViewDialogProps(props)` takes none);
  Ripple's `getSurfaceEl` (`RippleDomRootOwnProps`, `RIPPLE_DOM_ROOT_PROPS`,
  `rippleDomMachineProps`).
- **FileUpload:** the core contract is generic over the platform's file,
  `F extends FileUploadItem = FileUploadItem` (`{ name, size, type }`, exported); binding-dom has
  `FileUploadDom{BehaviorProps,RootOwnProps,ValueDetails,ContentProps}` over `File`, which React and
  Solid use.
- **Globals:** `hasEyeDropper` reads `globalThis` (React Native's web build still uses it);
  `pickerLocale` and `numberFieldLocale` read `platformLanguage()` (`platform.ts`); the globals every
  platform has (`console.warn`, `setTimeout`, `queueMicrotask`) are declared in
  `platform-globals.d.ts`.
- **`@pureform/binding-core/dom` removed**, no shim; imports in React and Solid rewritten (and
  comments in `machines/src/dialog.ts`, `binding-core/src/overflow.ts`, the design doc). Indication
  imports in React and Solid split between `binding-core/indication` and `binding-dom/indication`.
- **Guards:** binding-core's `tsconfig.json` has `lib: ["ESNext"]`, `types: []` and excludes specs;
  `tsconfig.spec.json` checks the specs with the DOM. binding-core's `test:unit` runs
  `package.json`'s `test:unit` script: `tsc` on both configs, then Vitest (omni's `exec` isn't a
  shell, so `&&` needs the script). `react-native/src/no-dom.spec.ts` (source glob, browser) and
  `rn-adapter/src/no-dom.spec.ts` (node fs) check that neither package's source nor `package.json`
  names `@pureform/binding-dom`.
- **Docs:** READMEs of binding-core, binding-dom (new), react, solid, react-native; binding-dom
  CHANGELOG; design doc §9.8 "Where it lives".

What r11's phase file lists but needed no change: `className`, links' `target`/`rel` and DOM event

## Refactoring hints

- **Helpers that look generic:** `platformLanguage()` (`binding-core/src/platform.ts`) is the one
  place to read the platform's locale; a future date/time or number component should use it
  rather than `navigator`.
- **Code that looks like a sibling's:** `webIndication` (binding-dom) and React Native's
  `nativeIndication`/`withNativeRipple` do the same thing per platform (map binding-core's Material
  indications to one with a live half, cached by identity).
- **Suggested home:** if a third platform appears, a small `withLiveHalf(indication, half)` in
  binding-core's `indication-material.ts` could serve both.
- **What must not change:** binding-core's `tsconfig.json` without the DOM lib, the two
  `no-dom.spec.ts` guards, and `IndicationPlatform`'s augmentation in binding-dom's
  `indication.ts` (removing it turns every web indication's elements into `unknown`).

## Open questions

- binding-core's `materialIndication()` now has no `web` half: an app (or test) that called
  `materialIndication().web` directly from binding-core gets `undefined`; through a web binding it
  behaves as before. Breaking for direct binding-core users, recorded in the commit.
- The `IndicationPlatform` augmentation applies to any program that loads
  `@pureform/binding-dom/indication`; a mixed web + React Native typecheck would see
  `HTMLElement` there too. Fine today; an alternative is a generic `Indication<E>`.
- binding-core's specs still run in Chromium (two use `document.createElement` as an opaque
  origin); they could move to Node.
- rn-web-demo's e2e is red on main (select menu → "Large" not found, cascading into 5 more
  failures). Needs its own fix, outside r11.
- tailwind-demo's `generate` can leave `.pureform/index.ts` naming files it didn't write when two
  gates run at once; worth checking whether generate writes atomically/clears `web/` first.
- `springRoleVar` (pure) moved with `settle.ts` to binding-dom, since only web code uses it.
