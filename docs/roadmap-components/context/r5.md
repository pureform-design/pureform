  that order. The text field, the select (so the autocomplete), the docked date picker and the

  tags input declare a different set and order, so they keep theirs.
- **`machinePart`** (Solid and React `parts.tsx`, from c5b's `time.tsx`): next to `plainParts`. It

  only `div` or `span`.
- **`useDateValue(component, props)`** (Solid and React `calendar-parts.tsx`, next to

- **`affixFieldParts(use)`** (Solid and React `select-field-parts.tsx`): the field half of

## Picker commit API (public change)

c5a left composed pickers committing differently: Solid had `CancelTrigger`/`ConfirmTrigger`
parts, React had `useDatePicker()`/`useDateInput()` hooks.

**Decision: parts, in both bindings.** Both bindings already close and confirm dialog-like
components through parts (`Dialog`/`FullscreenDialog`/`SideSheet` `CloseTrigger`, toasts'
`ActionTrigger`/`CloseTrigger`), so a part is each binding's convention. A hook was the odd one
out, and only in React. (`useTimePicker()` reads the machine's API in both bindings and stays.)

- React gains `DatePicker.CancelTrigger`/`ConfirmTrigger` and `DateInput.CancelTrigger`/
  `ConfirmTrigger`, from a new `react/src/picker-actions.tsx` (`pickerAction`, `PickerActionProps`),
  the same as Solid's: a `<button type="button">` or `as`, running the action unless the app's
  `onClick` prevents it. Spec: `date-input.spec.tsx` "DateInput, composed".
- **Removed:** `useDatePicker` and `useDateInput` from `@pureform/react/date-picker` and
  `/date-input` (a breaking change; the commit says so). The draft they returned is what
  `SelectedDate` shows.
- React's ready-mades still render `<Button onClick>` for Cancel and OK, not the new parts. Using
  the parts would add `type="button"` to those buttons, which changes the DOM (proposed change 1).

  surface, c5b's hint): **check 2.** The values differ: the date pickers' headline is
  `labelLarge` with a 36px gap under it, the time pickers' `labelMedium`; the date pickers' actions
  row has its own paddings, the time pickers' only a gap inside the root's padding; the date
  pickers' root is a 360px column with padded header rows, the time pickers' a padded column with
  a gap. One builder would need a flag per difference, or would change output. (M3 may want them
  the same; see open questions.)
- **The date picker's and date input's root** (`surface(...)` + `pickerChrome(ref).root`):
  **check 2.** The modal picker puts `overlayMotion` between the surface and the chrome, so
  folding `surface` into `pickerChrome` reorders its keys (output). The container ref differs too
  (`pickerContainer` vs the field's `container`).
- **The dialog and full-screen dialog vs the pickers:** nothing left. They already share
  `surface()`, `overlayMotion`/`DIALOG_MOTION` (preset) and `dialogParts` (bindings), which the
  modal date picker uses.
- **A whole `fieldComponent({ extraSlots, rootAs })`** (c5a's hint) for select, docked picker and
  date input: **check 2.** Beyond the variant groups (extracted) the recipes differ: the date input
  moves the field's root under `field` and its variant roots through `underField`, the docked
  picker adds a popup and the calendar, the select turns its arrow. It would need the options the
  hint names, so only the shared declaration moved.
- **Binding header parts (`Header`, `Headline`, `SelectedDate`, `ModeToggle`) of the date picker
  and date input:** **check 2.** The picker's come from `dialogParts` (`Headline` is an `h2` with
  the dialog's title props, `ModeToggle` a dialog trigger); the input's read its own context
  (`Headline` a `span` with its own id). Their plain parts now both come from `plainParts`.
- **The time pickers' headline and actions against the date pickers' (bindings):** **check 1.**
  The time pickers have no header, selected value or mode toggle; their headline and actions are
  `machinePart`s of their own machine.
- **Selection state (calendar vs list and tabs):** **check 1.** The calendar cell mixes its
  colours through 0%/100% flag tokens (`selected`, `ranged`, `today`) set by three variant groups,
  since a cell is selected, in a range and today at once. The list item and tabs read the
  `selected` state of `aria-selected` with a container and content per colour group. Only the
  word is shared. The `blendColor(from, to, flag)` c5a suggested has one user (the cell); leave

- **Locale helpers** (`localeHourCycle`/`localePeriods` in machines, `weekStartOf`/`weekdayLabels`/

  opposite dependencies (machines can't import binding-core).
- **React Native `TimeButton` into `SurfaceButton`** (c5b's hint): **check 2.** `SurfaceButton`

- **React Native modal date picker vs `ModalDialog`:** already on `useModalOverlay`,

## Refactoring hints (for c6)

- **Reuse:**
    - A field with a leading icon, affixes and supporting text over a Zag machine (c6's paginator's
      page-size select, a table's filter field): `affixFieldParts` (bindings) and
      `affixFieldVariants` with `affixField` (preset). A select-like one: `selectField`/
      `selectFieldParts`.
    - Parts that are an element with the user's props: `plainParts`; with machine props:
      `machinePart` (both in `parts.tsx`).
    - Confirm/cancel actions of a composed surface: `pickerAction` (both bindings'
      `picker-actions.tsx`) as parts, not hooks.
    - ISO dates in and out of Zag: `useDateValue`, `parseDate`/`parseIso`, `toISO`.
    - A React Native field that opens a popup from its trailing icon: `useFieldPopup`, then
      `Portal` and `Anchored`.
    - Anything dialog-like: `dialogParts` (Solid/React), `useModalOverlay` (React Native).
    - c6's stepper and accordion headers: `surface()`, `pressableRoot`, `stateLayer`.
- **Avoid:** two variant groups setting one property on a slot (`variant-overlap.spec.ts`), and a
  new number in the design docs without its counting rule (`doc-counts.spec.ts` covers only the
  two counts).

## Proposed intended changes (not done; each changes output)

1. **React ready-made date picker and date input actions as the new parts** (`CancelTrigger
as={Button}`): the buttons gain `type="button"`, as Solid's already have. Inside a `<form>`, a
   button without it submits the form, so this is also a fix. It changes the React DOM and
   possibly the indication fixtures.
2. **One picker chrome for the date and time pickers** (headline type role, actions row padding),
   if M3 gives them the same values: changes the time pickers' or date pickers' CSS and
   screenshots.
