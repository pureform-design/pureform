## Decided work

- **Shared isolation helper.** `isolated` (`{ isolation: isolate }`) and `stackAbove()`
  (`{ zIndex: unitless(1) }`) in `packages/preset/src/components/shared.ts`. The list item's swipe
  frame and row, the tabs' root and indicator, and the switch's root and input use them. Tabs'
  root changes `zIndex: 0` (with `position: relative`) to `isolation: isolate`, the same stacking
  context; the switch's root is now isolated, so its input's `z-index: 1` stacks only against the
  track. Two preset snapshots changed accordingly (`controls.spec.ts.snap` switch root gains
  `isolation`; `new-components.spec.ts.snap` tabs root `zIndex: "0"` → `isolation: "isolate"`), and
  `tabs.spec.ts`'s stacking assertion reads `isolation`. `visual.e2e.test.tsx` and
  `rn-parity.e2e.test.ts` passed unchanged (65/65, no screenshot re-recorded); `parity`,
  `indication`, `rn-indication` narrowed to tabs/switch/list passed.
- **Spring roles on Panda.** `PandaCodegenOptions.pandaPrefix` (Panda's own `prefix`, the same name
  `compilePreset` takes); `tokenPrefix` defaults to it, so `vars.tokenPrefix` and the factories'
  role vars (`--<prefix>-springs`) match Panda's token vars. An explicit `tokenPrefix` still wins.
  Tests in `panda-adapter/src/codegen.spec.ts` (a `slide` component with a spring token).
- **React Native role names.** `nativeFactory(component, styles, tokens?, springs?)`: a string is
  read as a role only on a token in `springs`; the codegen writes the shape's `springs` as the
  fourth argument. Test: `factory.spec.ts` "takes a role's name only on a spring token" (and the
  existing role test passes `componentShape(...).springs`).
- **`onClose` and controlled `open`.** The React, Solid and React Native READMEs, binding-core's
  README and `BottomSheetCloseProps.onClose`'s doc say closing through a controlled `open` doesn't
  ask, by design (as Radix and MUI).
- **Menu groups' `first`/`last`.** Restored on the machine as an override:
  `getItemGroupProps({ id, first?, last? })` writes `data-first`/`data-last` for `true`, plus
  `data-pf-first`/`data-pf-last` (`"true"`/`"false"`) saying it was given. `markMenuGroupEdges`
  marks by DOM order except an edge the group was given, which it sets as given (it also watches
  those two attributes, so dropping an override re-marks). React's and Solid's `ItemGroup` take
  `first`/`last`. Tests: binding-core `menu-groups.spec.ts` (override and its removal), React and
  Solid `menu.spec.tsx` "takes a group's own first and last over where it is". Documented in the
  machines, binding-core, preset, React and Solid READMEs and the gap analysis.

## Extracted

Each passed the three checks (same concept, obvious duplication, shared code takes future
changes).

- **`isSpringToken(node, { config?, target? })` and `tokenAt(config, path)`** (core `path.ts`).
  generate's `isSpring` (`shape.ts`) and css-lowering's `isSpringValue` were the same switch; they
  differed only in the platform rule, now the `target` option (without one, every choice has to
  be a spring, generate's rule; with one, that target's choice, the lowering's). css-lowering keeps
  `isSpringValue` (exported) as a one-line wrapper, and gains the cycle guard generate had.
  `tokenAt` (catching only `ConfigPathError`) replaces css-lowering's local `tokenAt` and the
  try/catch in rn-adapter's `springFieldNodes`. Tests in `core/src/path.spec.ts`.
- **`SPRING_FIELDS`** (rn-adapter `values.ts`): the factory had its own copy of lower's list (its
  comment said so). In `values.ts` the runtime factory imports it without importing the lowering.
- **`drag(element, moves, from?)`** (react-native `testing/render.tsx`): f2c's `dragDown` and the
  list item swipe spec's inline mouse drag; one move per task. The sheet keeps its start (4px into
  the handle) through `from`; the swipe now moves one task at a time, as f2c's hint suggested.
  (`laidOut` was already there since f2c.)

## Declined, with the failing check

- **`springValues` vs `springTokenValues`** (f2e): numbers for the runtime factory vs nodes for the
  lowering; deriving either from the other would pull node lowering into the runtime factory or
  wrap numbers in nodes to unwrap them. The shared part is two calls (`sampleSpring`,
  `dampingCoefficient`) (check 2). The field list they share is now one `SPRING_FIELDS`.
- **`springFieldNodes` on `isSpringToken`**: it returns the five field nodes (role refs, a
  `dynamic`'s per-field keys), not a yes/no; folding it in would make `isSpringToken` return
  nodes for one caller (check 3). It shares `tokenAt`.
- **`onClose` on the dialog, full-screen dialog and side sheet** (`closeAsker`): wiring is one
  line each, but it adds a public prop and behaviour to three components on three bindings, not a
  refactor (check 1: nothing is duplicated today). Left for a fix or feature phase to decide.
- **`markMenuGroupEdges` for Select**: Select doesn't draw grouped corners; one user (check 2).
- **f2b's `sliderClearanceOf` / `unstyledToolbarProvidedTokens`**, **f2d's `arrowDirection`**:
  one user each (check 2), as their contexts say.
- **The React Native test registry's springs**: `presetRegistry` (react-native `testing/`) builds
  factories without the spring-token list, so a spec there can't pass a role by name. No spec
  does; adding it needs `@pureform/generate`'s `componentShape` in react-native's test commands,
  a new dependency for one unused path (check 2).

## Refactoring hints (for m3's authors)

- **Reuse:** `isolated` + `stackAbove()` for any part that must draw over a sibling (don't write
  `zIndex: unitless(1)` again); `isSpringToken`/`tokenAt` for any "is this a spring" or "resolve if
  it exists" question; rn-adapter's `SPRING_FIELDS` for the five spring keys; react-native's
  `drag` for any drag spec, `laidOut` before reading a measured size. r7's list
  (`springState`, `springTo`, `springTweens`, `turnedOver`, `shapeTransition`,
  `swallowNextClick`) still holds.
- A new spring token is found by the shape automatically; the codegens pass it to the factories
  (web `springs` vars, React Native's fourth argument), so a role by name works with no extra code.
- **What must not change:** the preset snapshots as of this branch, `visual` screenshots,
  `rn-parity`, `menu-groups.spec.ts`, the factory and codegen specs above.
