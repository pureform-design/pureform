# f1: Fixes after m2 (merge context)

Branch `f1-merge`, from main `c702bccf`. Merged in order: `f1d-sort-arrow`, `f1f-spring-tokens`,
`f1e-rn-tabs`, `f1b-controls`, `f1c-overlays`, `f1a-lists`; then the gate's fixes, the tab-order
fix and these docs. Commits: `git log c702bccf..f1-merge`.

## What each subphase did

- **f1a, lists and navigation** ([f1a](f1a.md)): rail destinations take a `section` string,
  grouped through the now generic `selectItemGroups` (`navigationSections`); `sectionLabel` on a
  destination is removed. Selection list defaults to `single`. React Native's avatar is
  `role="img"` only when named. A swipeable list item sits in a new `frame` part with its `action`
  as the row's sibling, so an expandable item (or a link, a button) swipes too; the row itself
  slides; `ListItem.Frame` replaces Root's swipe props.
- **f1b, controls** ([f1b](f1b.md)): the shaped icon button's fallback border follows the size;
  chips rest on `medium` corners and press to `small` (Compose `ChipsTokens`); the text field label
  floats on `effectsDefault`; an unstyled vibrant toolbar recolours its icon buttons (React,
  Solid); the slider's inset icon cut-off reads the theme's `insetIconSize`/`insetIconPadding`
  (from layout on the web, from the resolved style on React Native).
- **f1c, overlays** ([f1c](f1c.md)): React Native sheets slide from their edge; a refused close
  after a drag springs back (both platforms); the drag view takes the standalone sheet's placing
  style; a web dismissing drag leaves from where it was released; the toast shrinks to 80% on exit
  (CSS `scale`, added to core's style types); grouped menus no longer clip submenus on the web.
- **f1d, table sort arrow** ([f1d](f1d.md)): core's `descending` state (`[aria-sort=descending]`
  on the web, a React Native state); the arrow is always ↑ and turns on `spatialFast`.
- **f1e, React Native tabs spring** ([f1e](f1e.md)): the indicator's slide on Animated runs a real
  spring (`settle()`), and an interrupted slide keeps its speed (`springProgress`).
- **f1f, spring component tokens** ([f1f](f1f.md)): a component token can hold a spring (literal or
  role alias); the web writes `<token>-duration`/`<token>-easing` falling back to the role's vars;
  React Native resolves it to a real spring through `$dyn` keys. Tabs `indicatorSpring` and time
  picker `handSpring` are back.

## Fixes at the merge

- **Swipeable list item tab order** (`b2f17f48`): the action now follows the row in the frame,
  `[root, action]`, in React, Solid and React Native, so Tab (and React Native's accessibility
  order, which follows view order) reaches the row before a revealed action. The swipeable row
  gets `zIndex: 1` (`unitless(1)`, like the tabs indicator and switch input; not a theme
  `zIndex` role, which would escape the frame), so it paints over the action as before. The row
  is already `position: relative`. Specs: the frame's children order in the React, Solid and
  React Native specs; preset `nested.spec.ts` checks the row's z-index; snapshot
  `new-components.spec.ts.snap` (listItem `swipeable.true.root`). READMEs and the gap analysis say
  so.
- **Solid slider inset icon** (`40226319`, from f1b): its effect read `api()` and `measures()`
  outside the compute, which Solid 2 warns about (`STRICT_READ_UNTRACKED`), failing the
  server-rendering suite's "hydrates without a warning" for the inset-icon sliders on all three
  Solid targets. Both are now part of the compute.
- **rn-parity** (`12fac639`, from f1c): a grouped menu's first/last `itemGroup` rounds its outer
  corners only on the web (React Native keeps the clip), so the parity test skips `itemGroup`
  radii for the menu.
- **Chip screenshots** (`472e94d6`, from f1b): `chips` and `chip-sets-and-scrollable-tabs`
  updated for f1b's `medium` resting corners (the commit message says outline colour; the diff
  is at the corners).

## Refactoring hints (for r7)

Collected from the subphases, plus the merge:

- **f1a:** React's and Solid's `Frame` put their scope's root token style on a non-root part
  (`scope.classes.root?.style`): a `tokenStyleOn(part)` render option in
  `packages/{react,solid}/src/parts.tsx`. The swipe gestures' click swallowing differs (React
  capture prop, Solid native listener); the native listener works in both. `selectItemGroups` is
  generic now: tree or menu groups could use it.
- **f1b:** `readSliderInsetIcon` (binding-core `dom.ts`) and its React Native twin
  `sliderInsetIconMeasuresOfStyle`: a binding-core "resolved token reader" if a third component
  needs a theme value at runtime. The unstyled-toolbar `ProvidedTokens` wrapper in React and Solid
  toolbars.
- **f1c:** `placement()` (`react-native/src/bottom-sheet/bottom-sheet.tsx`) to
  `react-native/src/parts.tsx` when a second wrapper view needs it.
- **f1d:** a `turnOver(condition, fades)` beside `chevronTransition` in `shared.ts` if a third
  turning icon fades `opacity` (`expandIndicator` and the sort arrow today).
- **f1e:** the `Animated.spring` start with rest thresholds in `useAnimatedSlide`
  (`rn-adapter/src/animate/slide.ts`) and `animate()` (`animate/curve.ts`); `springProgress` could
  serve presence and overlay interrupts.
- **f1f:** one "spring value's fields" helper for `rn-adapter/src/theme.ts`'s two loops and
  `springNodes`' `dynamic` case.
- **Merge:** a plain `unitless` z-index to stack siblings appears in tabs, switch and now the list
  item; a named "above a sibling" helper (or a local stacking token) in `shared.ts` would say
  why. Keep the swipeable row's computed styles identical.
- **What must not change:** the subphases' lists, plus `nested.spec.ts`'s stacking spec, the
  frames' order in the three list item specs, rn-parity and the chip screenshots.

  item that doesn't expand still can't take `onPress`; the web selection's `swipeable` variant and

  `scale` rather than `overlayShrinkOut`; grouped menu corners use raw `:first-child`/`:last-child`;

  setup runs the e2e suites as part of `build`.

  overshoots under expressive; no web assertion of the rotated transform in a binding spec.
